# Investigación: hechos en que se apoya la feature 030

Leídos entre el 2026-11-06 y el 2026-11-07, con Claude Code 2.1.319 instalado. Cada hecho dice su fuente. Lo que dice «sin documentar» no se debe dar por cierto sin probarlo.

## 1. Claude Code

**Hooks** (https://code.claude.com/docs/en/hooks)
- Campos comunes: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`, `effort`. `agent_type` está presente cuando la sesión usa `--agent` o el hook corre en un subagente; en un subagente gana el tipo del subagente. `agent_id` solo existe en subagentes.
- **Stop**: «Runs when the main Claude Code agent has finished responding». Entrada: `stop_hook_active`, `last_assistant_message` (el texto de la última respuesta), `background_tasks`, `session_crons`. En subagentes corre SubagentStop, no Stop.
- **PreCompact**: entrada `trigger` (`manual` o `auto`) y `custom_instructions`. «When a PreCompact hook exits 0 and doesn't block, Claude Code uses its stdout as instructions for the compaction summary. Keep that stdout under 10,000 characters per hook.»
- **PostCompact**: entrada `trigger` y `compact_summary`, «the conversation summary generated by the compact operation». Sin control de decisión.
- **StopFailure**: entrada `error` (por ejemplo `rate_limit`, `overloaded`, `server_error`, `max_output_tokens`, `unknown`), `error_details` y `last_assistant_message` opcionales. Su salida se ignora.
- **SessionEnd**: entrada `reason` (`clear`, `resume`, `logout`, `prompt_input_exit`, `other`). Todos los hooks de SessionEnd comparten 1,5 s, y «Timeouts set on plugin-provided hooks don't raise the budget»: el `timeout: 30` de `aether-observe` en `hooks/hooks.json` no lo amplía. Lo que escriba la continuidad ahí tiene que ser mínimo y rápido.
- **SessionStart**: `source` es `startup`, `resume`, `clear`, `compact` o `fork`; trae `agent_type` con `--agent`. `additionalContext` tiene un tope de 10.000 caracteres.
- **PermissionRequest**: entrada `tool_name`, `tool_input`, `permission_suggestions`. Para permitir: `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}`. Corre «only when Claude Code is about to ask you for permission», también en sesiones que no pueden mostrar el aviso. Las reglas deny siguen valiendo.
- **WorktreeCreate**: «Configuring a WorktreeCreate hook replaces that default git behavior»; si falla o no imprime una ruta, la creación falla; las copias de subagentes que crea no se borran al terminar el subagente. Por eso esta feature no lo usa.

**Prueba propia de `.claude/`** (2026-11-06, `claude -p` en Haiku, sin ajustes del usuario, una corrida por caso, US$ 0,02; guion en el scratchpad de la sesión e68e9fb9):
- Un hook PreToolUse que responde `allow` NO evita el aviso de ruta protegida, ni en `default` ni en `acceptEdits`.
- Un hook PermissionRequest que responde `allow` SÍ lo evita, en los dos modos.
- Un script de Node lanzado por un comando Bash permitido escribe en `.claude/` libremente.
- `.claude/agent-memory/*.md` es libre; en modo `auto` la escritura pasó.
- No probado: una sesión interactiva, el `tool.check` del mod, repeticiones.

**Rutas protegidas** (https://code.claude.com/docs/en/permission-modes): `.claude/` está protegida salvo `.claude/worktrees/`, los planes, el Markdown de la memoria automática y `.claude/agent-memory/`. `.claude/skills/` y `.claude/rules/` no están exentas. «`permissions.allow` rules in settings files do not pre-approve protected-path writes.»

**Skills** (https://code.claude.com/docs/en/skills): «a `<skill-name>` entry in the enterprise, personal, or project location can be a symlink to a directory elsewhere on disk». Un enlace `.claude/skills/<nombre>` → `.agents/skills/<nombre>` carga. Los subagentes no heredan las skills de la sesión; el campo `skills:` de un agente las precarga. SKILL.md conviene por debajo de 500 líneas; la lista de skills ocupa como máximo el 1 % del contexto.

**Memoria** (https://code.claude.com/docs/en/memory)
- «The `<project>` path is derived from the git repository, so all worktrees and subdirectories within the same repo share one auto memory directory.» La regla exacta del nombre no está documentada. En la máquina del dueño es la ruta del checkout principal con cada carácter que no es letra o dígito cambiado por `-`: `/home/<usuario>/Desktop/03_PROYECTOS/01_ACTIVOS/aether-plugin` → `-home-<usuario>-Desktop-03-PROYECTOS-01-ACTIVOS-aether-plugin`, y una sesión abierta en `.worktrees/skills-tree` usa esa misma carpeta de memoria.
- `autoMemoryDirectory` en los ajustes cambia la carpeta («an absolute path or start with `~/`»); `CLAUDE_CODE_PROJECT_DIR_NAME` cambia el nombre.
- Del índice `MEMORY.md` se cargan los primeros 200 renglones o 25 KB; los archivos de detalle no se cargan solos. El índice del dueño en este repo tiene 56 renglones y 13,5 KB, y más de 20 entradas son fotos del estado de versiones viejas.
- `CLAUDE.md`: menos de 200 líneas; `AGENTS.md` se lee solo si no hay `CLAUDE.md` (v2.1.277+); `@AGENTS.md` lo importa. `.claude/rules/*.md` cargan al inicio, o al tocar archivos que coinciden con su `paths:`. Existe `~/.claude/rules/` para todas las sesiones.

## 2. skills.sh (`vercel-labs/skills`, HEAD `d3701c1`, paquete `skills` 1.7.6, leído el 2026-11-07)

- **Instalar en un proyecto:** la copia real va en `<proyecto>/.agents/skills/<nombre>/` (`src/installer.ts:136-139`); cada agente que no lee `.agents/skills` recibe un enlace, Claude Code en `.claude/skills/<nombre>` (`agents.ts:169`); si el enlace falla, copia. `--copy` copia siempre. `-g` instala en `~/.agents/skills/`. `-y` sin `-g` instala en el proyecto.
- **Registro del proyecto:** `skills-lock.json` en la raíz (`src/local-lock.ts:6`), `{ "version": 1, "skills": { "<nombre>": { source, sourceUrl?, ref?, sourceType, skillPath?, computedHash, … } } }`. `computedHash` es SHA-256 sobre los archivos de la skill ordenados por ruta relativa (ruta y luego bytes, sin `.git` ni `node_modules`, sin enlaces) (`local-lock.ts:191-230`). No guarda el commit.
- **Registro global:** `~/.agents/.skill-lock.json`, versión 3, con `skillFolderHash` = el SHA del árbol de GitHub (otra clase de huella: no comparar con la del proyecto).
- **Fuente:** `owner/repo`, `owner/repo/ruta`, `owner/repo@skill`, `owner/repo#ref`, `github:`/`gitlab:`, URLs de GitHub y GitLab, rutas locales, URLs de otros sitios. El autor es el primer segmento de `owner/repo`, en minúsculas, después de resolver dos alias (`vercel-labs/vercel-skills` → `vercel-labs/agent-skills`, `coinbase/agentWallet` → `coinbase/agentic-wallet-skills`).
- **Comandos:** `list`, `find` (una consulta HTTP a `https://skills.sh/api/search`), `update`, `remove`, `install` (restaura desde `skills-lock.json`). Ninguno corre scripts de la skill bajada.
- No existe un CLI `ags` ni un archivo `skills.lock` en este proyecto.
- En la máquina del dueño hay 7 skills personales instaladas así: la copia en `~/.agents/skills/` y el enlace en `~/.claude/skills/`.

**Seguridad:** Snyk (feb. 2026) encontró 76 skills maliciosas entre 3.984 revisadas en clawhub y skills.sh; skills.sh audita solo una parte. Por eso el Lead lee cada skill completa antes de instalarla.

## 5. El código de Aether (main ac1e68a)

- Hooks registrados (`plugins/aether/hooks/hooks.json`): SessionStart (notas y partes), PreToolUse (guard), PostToolUse de ScheduleWakeup, PostToolUseFailure, StopFailure, PreCompact y SessionEnd (los cinco de `aether-observe`, que no imprime nada). No hay Stop, PostCompact ni PermissionRequest.
- Sesión del Lead: `isAetherSession(dataDir, session_id)` (`lib/session.js:157`), una marca que `aether-session-start` escribe en `<datos>/sessions/<id>.json`.
- Rutas de `.aether/`: `lib/run.js:36-49`, `worktrees.js:42,46`, `seats.js:924` (seats), `seat-calls.js:94` (mensaje en `.aether-tmp/seats/`), `delegate-calls.js:233` (delegados), `exam.js:14,133`, `lane-work.js:21-30` (lanes), plantillas en `workflows/*.workflow.js`, prompts en `agents/implementer.md:22` y `agents/examiner.md`. `.aether-exam/` y `.aether-tmp/` salen de git por `info/exclude` (`run.js:15,138-150`).
- Limpieza: `sweepStale` (`worktrees.js:1390`) borra corridas, copias de unidades y de lanes de más de 24 h; no toca seats, delegados, `.aether-tmp/` ni el mensaje de seats. Su marca de 10 min es una sola para todos los proyectos (issue #186). Las podas de 30 días (`session-start.js:163`) cubren observación, uso, registros de lanes, sesiones y el registro de delegados.
- Encargos de delegados: `parseBrief` (`lib/delegate-task.js:52-77`) lee `AETHER-TASK`, `AETHER-OWNS` y `AETHER-TESTS`; el texto final se arma antes de `fullPrompt` (435) y llega a Claude y a otros harness (439-440); el registro `launch` está en 491-496. Las skills de Aether ya se pegan así en los asientos externos (`skillBody`, `lib/seats.js:554`).
- Campos de `tasks.md`: `parseAetherFields` (`lib/plan.js:149-216`) ignora en silencio un campo que no conoce; el encargo de cada unidad lo escribe `renderBrief` (`plan.js:460-486`).
- Agentes: solo el Writer tiene la herramienta Skill; ninguno tiene `skills:`.
