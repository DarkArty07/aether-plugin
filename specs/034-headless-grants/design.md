# Design: the text a session is launched with does not record the owner's authorizations

- **Feature:** `specs/034-headless-grants`
- **Author:** the Lead (Fable 5.2), 2026-11-11.
- **Route:** short design. It changes who may record an authorization for an irreversible action, so it touches security and authorization.
- **Scope:** `aether-autonomy grant`, `trust` and `brake-off`, and how `check` reads a stored grant. `start`, `revoke` and `aether-delegate authorize` keep today's behaviour.

## The owner's words

Session of 2026-11-11. The owner asked the Lead to analyse issue #1 again («quiero que lo incluyas a tuy trabajo analiza el issue 1. d enuevo ya esta cerrdado»). The Lead proposed to close the point below before anything else of issue #1. The detail is kept in a private draft security advisory; the documents of this change say the rule and nothing more. The owner answered «si a todo lo que ncesitas y lo que necesitas para continaur sacalo tu» and then approved the run's plan, whose third assumption reads: «Una sesión sin terminal ya no puede registrar permisos, confiar en un autor de skills ni apagar el freno de cuota con el texto con que se lanzó. Abrir una corrida y colocar un delegado en un modelo siguen como hoy. Consecuencia: si tú mismo lanzas una sesión con `claude -p`, el permiso para fusionar o publicar se registra antes, en una sesión normal.»

## The rule and the field it relies on

- `verifyQuote` in `plugins/aether/lib/autonomy.js` checks a quote against the owner's messages of the session, which `ownerMessages` in `plugins/aether/lib/voice.js` takes from the session's transcript.
- Three authorizations need more than that: an authorization for an irreversible action (`grant`), a trusted skill author (`trust`) and turning the quota brake off (`brake-off`) are recorded only from words typed in a session with a terminal. A session without a terminal has no typing: the text it was launched with is not the owner's words for these three.
- The field that tells them apart is the record's `entrypoint`. In the transcripts of this project (73 conversations, read on 2026-11-11 for the fields `entrypoint` and `origin` only, never their text) every record a person typed has `entrypoint: "cli"` and `origin` `human`, including the queued prompts typed while a turn runs (19 attachment records, `commandMode: "prompt"`, all `cli`); the launch text of each of the two sessions without a terminal has `entrypoint: "sdk-cli"` and no `origin`. `start` already relies on the same field and fails closed on one it does not know: `isHeadlessTranscript` (`lib/autonomy.js`, about line 76) and the test at `tests/autonomy.test.js` line 637.

## Criteria

- **C1** A quote verifies for `aether-autonomy grant`, `trust` (adding an author) or `brake-off` only when it is in a message typed in a session with a terminal: a message whose record's `entrypoint` is `cli`. A record with any other entrypoint, with an unknown one or with none is not typed. When the quote is found only in messages that are not typed, the command refuses, writes nothing, and says why and where to record it: in a session with a terminal.
- **C2** In a session with a terminal the three commands work as today.
- **C3** A grant already in the registry whose quote is found only in messages that are not typed no longer covers anything while its transcript exists: `check` skips it, and `aether-autonomy list` shows it with the status `not-typed`. A trusted author or a brake-off already recorded is not re-read; see the accepted limits.
- **C4** `start`, `revoke` and `aether-delegate authorize` verify a quote as today, launch text included: a session without a terminal still opens a run and places a delegate on a model, and may still withdraw a grant.
- **C5** `npm test` and `npm run test:mod` pass. The tests that record a grant, a trusted author or a brake-off from a launch text are moved to a typed message, and only those.

## Design

**D1. A message knows whether it was typed.** `ownerMessages` in `lib/voice.js` returns, with each message, `typed: true` when its record's `entrypoint` is in the list `TYPED_ENTRYPOINTS`, which holds `'cli'`, and `false` otherwise: another entrypoint, an unknown one (the Agent SDK's and the GitHub Action's among them) and none are all `false`. It is an allowlist, as `start` is, so a session that is not known to have a terminal is refused. Whether the messages typed in an IDE or desktop session count is the owner's to say; adding one is one entry of the list and a test. The rule is by record, not by transcript, so a session that was launched without a terminal and later continued in one keeps its typed messages. It is read from the record the message comes from, queued prompts included: the attachment record of a `queued_command` with `commandMode: "prompt"` carries its own `entrypoint` (read in real transcripts, above), and `typed` is taken from that one. What `aether-voice` prints does not change.

**D2. Three commands ask for typed words.** `verifyQuote` takes an option `typedOnly`. With it, the quote is searched only in the messages that are `typed`. `grant` (`grant` in `lib/autonomy.js`), `trust` (`trustAuthor`, when it adds an author) and `brake-off` (`brakeOff`) pass it; `start`, `revoke`, `delegate-authorize` and `trust` when it removes an author do not: withdrawing an authorization is never refused for where the words came from. When the quote is in a message that is not typed and in no typed one, the refusal's reason is: `this quote is not in words typed in a session with a terminal: record it in a session with a terminal`. The other refusals keep their words.

**D3. A stored grant is read by the same rule.** The reader that `check` and `list` use to re-verify a stored grant against its session's transcript passes `typedOnly` too. A grant whose quote is only in messages that are not typed gets the status `not-typed`; `check` skips it as it skips `invalid`. A grant whose transcript is gone is still returned, as today: nothing can be said of it (see the accepted limits for the step that closes that).

**D4. Records.** `docs/guide/autonomy.md` says that an authorization is recorded only from words typed in a session with a terminal, and what a session without one may still do. The changelog entry says the same and names no way to misuse an older version. The guide also gives the step after updating: `aether-autonomy list`, and for any grant with the status `not-typed`, or whose transcript is gone and whose origin the owner cannot vouch for, `aether-autonomy quarantine grants` sets the file aside and he records again, in a session with a terminal, what he wants; for trusted authors, the log in `skills/trusted.json` of the data directory says in which session each was added, and `aether-autonomy trust --remove` withdraws one. The Lead's rules get one sentence, in «Recording the owner's authorizations» of `skills/using-aether/SKILL.md`: «In a session without a terminal no authorization can be recorded: put the action in the owner's list.» If that sentence takes a part of the bootstrap over 9,800 characters, it is left out and the Lead learns it from the refusal's message; no other rule is shortened to make room.

## Accepted limits

- A process that can type into the owner's terminal, or write a transcript file, is the owner for this check. The check keeps words that were not typed from counting as his; it is not a defence against a process that already acts as him.
- A trusted author or a brake-off recorded before this change is not re-read: `trusted.json` keeps authors without re-verifying them, and a run's `brakeOff` is obeyed as stored. Re-reading them on every use would touch the guard's reader and every place a run is read, for a window that a run's ceilings and the owner's review (D4) already bound: a brake-off ends with its run, and a trusted author is withdrawn with `trust --remove`, which is never refused.
- A grant whose transcript is gone is still returned, so a grant recorded before this change from words that were not typed covers again if Claude Code prunes that transcript. The step is in D4: list, quarantine, record again. Recording the status in the registry the first time `check` finds it was left out: `check` does not write today and the guard calls it on every command.
- A transcript whose records have no `entrypoint` (a version of Claude Code older than the ones read) verifies nothing for these three commands; the owner records again in a current session.
- Opening a run and placing a delegate from launch text stay possible. They authorize reversible work and its cost; every irreversible action inside such a run still needs a grant, which now cannot come from that text.
- The owner's own scripts that launch a session without a terminal can no longer record a grant inside it. He records it first in a session with a terminal, with scope `repo`; the launched session's `check` then finds it.
- The field `entrypoint` is Claude Code's. If a later version names a typed message differently, the rule stops matching and refuses a typed quote (the command says where to record it); it never accepts words that are not typed. The test of D1 pins the value read from real transcripts, and the design says where it was read.
- Only two transcripts of sessions without a terminal were available to read the field from.

## Tests

In the style of `tests/autonomy.test.js` and `tests/aether-autonomy.test.js`, whose helper `human()` writes a transcript line with a chosen `entrypoint`. Written first and seen failing.

1. A transcript whose only owner message has `entrypoint: "sdk-cli"` (with `origin: { kind: "human" }` and also with no `origin`, as the real records are): `grant`, `trust` and `brake-off` refuse with the reason of D2. Each leaves its own file untouched: `grant` `.aether/autonomy/grants.json` (absent stays absent), `trust` `skills/trusted.json` in the data directory, `brake-off` the open run's `run.json` (`brakeOff` stays `null`).
2. The same quote in a typed message (`entrypoint: "cli"`): the three succeed as today. A record with no `entrypoint`, one with an unknown entrypoint (`"desktop"`, `"sdk-ts"`) and one with a number: the three refuse as in 1.
3. A transcript with the quote in a message that is not typed and, later, a typed message that does not hold it: refused. With a typed message that holds it: accepted, and the grant's time is the typed message's.
4. `start`, `revoke`, `trust --remove` and `delegate-authorize` with a quote that is only in a message that is not typed: accepted, as today.
5. A registry that holds a `repo` grant whose quote is only in messages that are not typed: `check` does not cover its class, from the same session and from another session of the repository, and `list` shows the status `not-typed`. The same registry with its transcript removed: the grant is returned, as today. After `quarantine grants` it is not.
6. `tests/voice.test.js`: `typed` is true for a `cli` record and false for `sdk-cli`, an unknown entrypoint and none; a queued prompt (`attachment`, `queued_command`, `commandMode: "prompt"`) is `typed` from its own record's `entrypoint`, true with `cli` and false with `sdk-cli` or none, and `grant` accepts a quote that is only in a typed queued prompt and refuses one in a queued prompt of `sdk-cli`; the text and time of each message are unchanged.
7. The existing tests that record a grant, a trusted author or a brake-off get `entrypoint: "cli"` per call, not by changing a helper's default, so the tests of `start` without a terminal keep `sdk-cli`. The files known to be affected: `tests/autonomy.test.js`, `tests/aether-autonomy.test.js`, `tests/quota-brake.test.js` and `tests/quota-brake-scenarios.test.js` (their `human()` defaults to `sdk-cli`), and `tests/autonomy-trust.test.js`, `tests/guard-skills.test.js`, `tests/guard-tidy.test.js`, `tests/guard-merge-main.test.js` and `tests/guard.test.js` (their transcripts have no `entrypoint`, which no longer verifies). The implementer finds any other with a search for `.grant(`, `trustAuthor`, `brake-off` and `aether-autonomy grant|trust` in `tests/`.
