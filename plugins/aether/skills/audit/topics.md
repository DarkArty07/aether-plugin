# The topics of an audit

The catalog `/aether:audit` proposes from. Each reviewer gets its row's «what to look for» in its brief. A topic is proposed only when the automated analysis or the project shows it applies; `performance` and `accessibility` above all.

| id | name | what to look for | sources |
|---|---|---|---|
| bugs | Bugs | Logic that gives a wrong result, unhandled edge cases (empty, null, zero, very large, concurrent), errors swallowed in silence, a promise or a resource never awaited or closed. Start in the hotspots: change frequency with size is where defects concentrate. Only what you can point to with the input that triggers it. | https://github.com/anthropics/claude-plugins-official/blob/main/plugins/code-review/commands/code-review.md, https://docs.enterprise.codescene.io/versions/6.6.7/guides/technical/hotspots.html |
| security | Security | Input that reaches a query, a shell, a path or HTML unchecked; missing authentication or authorization on an entry point; secrets in the tree or the history (type, file and line only); unsafe defaults (debug on, permissive CORS, broad file modes); data sent or logged that should not be. | https://asvs.owasp.org/, https://owasp.org/www-project-code-review-guide/ |
| dependencies | Dependencies | Known vulnerabilities the analysis reported and whether the vulnerable code is reachable; versions not pinned or a missing lockfile; licenses that conflict with the project's; CI workflows with broad permissions or unpinned actions. | https://github.com/ossf/scorecard/blob/main/docs/checks.md |
| tests | Tests | Tests that fail in the analysis and why; critical paths with no test; tests that assert nothing or only that no error was thrown; tests that depend on time, order or the network and fail now and then; a test command that does not run all the tests. | https://pitest.org/quickstart/basic_concepts/, https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html |
| reliability | Reliability | Calls to an external service or process with no timeout, no retry limit or no handling of its failure; what happens on a crash halfway (partial writes, non-atomic files); errors that are logged nowhere; resources that grow without bound. | https://sre.google/sre-book/launch-checklist/ |
| performance | Performance | Only when the project has performance goals, a hot path or a measured complaint: work repeated in a loop, a query per item, a whole file or table read to use a part, blocking calls on a request path. | https://www.iso.org/standard/78176.html |
| accessibility | Accessibility | Only when the project has a user interface: images without alternative text, controls without a label, color as the only signal, keyboard traps, contrast. | https://www.iso.org/standard/78176.html |
| architecture | Architecture and debt | The hotspots with poor health (large, much changed, many reasons to change); modules coupled so that one change needs many files; dead code; logic duplicated in two places that must stay in step. Stable debt nobody touches ranks low. | https://docs.enterprise.codescene.io/versions/6.6.7/guides/technical/hotspots.html, https://martinfowler.com/bliki/TechnicalDebtQuadrant.html |
| docs | Documentation against code | Commands, options, flags, file paths, examples and versions the README and the docs state that the code no longer has or does differently; setup steps that would fail; a feature the docs promise that is not there. Run nothing to check: compare the text with the code. | https://www.writethedocs.org/guide/tools/testing/, https://www.diataxis.fr/start-here/ |
| releases | Versions and releases | The version stated in more than one place and not the same in all; a changelog that misses the latest release or is not dated; tags that do not match the versions; a breaking change in a minor or a patch. | https://semver.org/, https://keepachangelog.com/en/1.1.0/ |
| hygiene | Repository hygiene | Branches the analysis lists as stale that hold work not in the default branch; pull requests and issues open for a long time that are already done or no longer apply; TODO and FIXME without context; CI that is red or disabled. Age is a reason to look, not a severity. | https://www.chaoss.community/kb/metric-issue-age/ |
| opportunities | Opportunities | What the project promises (a roadmap, a README section, a TODO of a feature) or what open issues ask for, that nothing implements yet; a small change that would remove a recurring manual step. Each with where it is promised or asked. | https://jules.google/docs/suggested-tasks/ |
