# Components

Every piece of the Aether plugin and what it does, and the footprint of Aether in a session that is not in Aether mode; the method they serve is in [Methodology](../methodology.md), and the options that change them are in [Options](../guide/options.md#options).

## The pieces

| Piece | What it does |
|---|---|
| `using-aether` skill | Injected at session start, in consecutive parts that each reach the Lead whole (issue #139). The Lead's rules: its role, RADAR, the method on Spec Kit's layout, the clarifying questions, the intent card and `/aether:design` with what to do for each of its four results, the exam, assumptions, the owner's list, the three paths (direct, delegate task, swarm), the delegate ladder (the Lead launches a delegate task with its task lines, the system holds the model, and the Lead judges each result), fallbacks, the rules of autonomous runs that hold outside a run (the irreversible classes, the grants, the repetition rule and the short brief) and the execution method |
| `autonomous-runs` skill | The Lead's procedure for a run of hours, loaded when the owner gives permission to work for hours or session start reports an open run: the start, the permission warnings, the diary, the rule of working on, the ceilings, the cost record, when a run is done, the honest stop, resuming and the brief |
| `aether:lead` | The Lead agent: the main session of Aether mode, started with `claude --agent aether:lead --effort xhigh`. It is not a subagent. It starts on Sonnet, and its rules are the `using-aether` skill's, which the SessionStart hook gives it in parts |
| `aether:writer` | The Writer agent: Sonnet at `high`. It writes `spec.md` from the intent card, and `plan.md` and `tasks.md` from the approved spec, with the Aether fields and a `Serves` line on each task, and checks them with `aether-plan check`. On a correction it edits the document in place and changes only what the Judge flagged. An external Writer in a seat runs at its pair's effort |
| `aether:judge` | The Judge agent: Opus at `high`, read-only. It reviews a spec, a plan or tasks, and rules `approve`, `revise` or `reject`, with at most ten findings, each typed `missing`, `extra` or `wrong`: what goes beyond the owner's intent is a defect, as much as what is missing |
| `aether:examiner` | The Examiner agent: Opus at `high`. It writes the hidden acceptance exam of an approved spec and plan under `.aether/exam/`, one command per test, without reading `tasks.md` |
| `aether-lane` | The commands of superdelegation: `status`, `pick`, `start`, `wait`, `result`, `stop`, `took`, `pause`, `quota` and `delegate`, which choose the pair for a call, run it on another harness's model, log which one took it, read each harness's quota, and run an editing delegate in a unit worktree. Whether a run uses them depends on the `superdelegation` option, off by default; see [Options](../guide/options.md#options) and [Lanes](../guide/lanes.md#lanes) |
| `aether-lane seat` | One round of a design seat (`judge`, `writer` or `examiner`) on the external pair the rule of [Lanes](../guide/lanes.md#lanes) chooses when `superdelegation` is on, in a disposable worktree of the commit; exit 3 or 4 hands the round to the native agent. The Judge and the Examiner take a pair of another family first, then the author's own family, and the native agent only last; the swarm and `aether-lane delegate` still bar the author's family. `/aether:design` runs a round in steps instead: `aether-lane seat-start` launches it, `seat-wait` waits for it within one ops call and `seat-stop` ends it |
| `aether-delegate` | The ladder of the Lead's delegate tasks: they start on Haiku, a rejected attempt rises one step to the next rung on the ladder, repeating changes outside Owns or the same blocked cause blocks the task on its rung, and infeasible with a reason rises (see [Delegates](../guide/delegates.md)). `verdict` and `authorize` are the Lead's: `verdict` judges the last result of a task as `approve`, `fix` or `infeasible`, runs the checks that need no model before an `approve`, and says what the next launch is; `authorize` records the owner's own words that place one task on Sonnet or Opus, and `begin` starts that task on the model they name (see [Placing a task](../guide/delegates.md#placing-a-task)). The mod runs the rest: `begin` fixes the model, effort and brief of the `Agent` call it caught, `start`, `run` and `wait` launch an attempt on another harness, do it and wait for its result, `answer` records the end of an attempt that ran on Claude: the final answer of a read-only delegate, or an `ended` mark, with no text, for one that edits, and `renew` takes a new quota reading of agy, codex, grok or muse. Each verb prints one JSON line, and none of them merges or pushes |
| `aether-exam` | Keeps an exam outside the repository (`store`) and runs it on a commit in a disposable worktree (`run`) |
| Aether preset | `plugins/aether/speckit/`: Spec Kit's specify, plan, tasks and constitution commands adapted to Aether, also shipped as the skills `aether:specify`, `aether:plan`, `aether:tasks` and `aether:constitution` |
| `aether-voice` | Prints the owner's own words from a session, so a quote can be checked; it writes no file |
| `aether-first-setup` | Installs a small command that starts Aether mode, `aeth` by default (`--name`), in the folder that `--dir` names or, without it, the one the rule below chooses. The command is a stub of POSIX sh with a marker line that runs the launcher of the newest installed release each time, so it never goes stale; only a version directory shaped like `0.12.3`, with a launcher that is an executable file, counts. A name is at most 64 characters, and not `claude`, which the launcher runs. It replaces only a stub of its own: a file of that name that is not one, or a command of that name on the `PATH`, makes it write nothing and exit 3. It never edits a shell file; when the directory is not on the `PATH` it prints the line to add for bash, zsh and fish. `--permissions autonomous|auto|ask` (default autonomous) writes `AETHER_PERMISSION_MODE` into the stub: bypassPermissions, auto or manual for `autonomous`, `auto` and `ask`, and a value the shell already sets wins. Without `--dir` it chooses `~/.local/bin` when that is on the `PATH`, else the folder of `claude` when it is inside the home and writable, else `~/.local/bin`, with the line for the `PATH`. `--check` writes nothing. It prints one JSON object, and exits 2 on a usage mistake |
| `aether-doctor` | Reads, never writes. It checks Claude Code 2.1.294 or later, Node 22 or later, git 2.36 or later, the installed release, the `aeth` command (`--name`) and the `PATH`, the dynamic workflows (`enableWorkflows`, `disableWorkflows`, `CLAUDE_CODE_DISABLE_WORKFLOWS`), the harness CLIs and whether the folder is a git repository. It prints one JSON object (`ok`, `version`, `installed`, `harnesses`, `options`, `command`, `checks`) and exits 0 when no check is an error, 1 with an error check, and 2 for a usage mistake |
| `setup` skill | `/aether:setup`, which the install line opens right after installing, and which the person can run again to change their choices. It sets `disable-model-invocation`, so the model never loads it on its own. It runs `aether-doctor`, asks in one AskUserQuestion call how `aeth` handles permissions (autonomous, auto or ask) and, when other harness CLIs are installed, whether to send them work; installs the command with `aether-first-setup --permissions`; saves `superdelegation` and `harnesses` with `claude plugin configure aether@aether-plugin --values-stdin`; and ends with one final screen. It replaces the `first-setup` skill of 0.12.4 to 0.29.0 |
| `doctor` skill | `/aether:doctor`, which sets `disable-model-invocation`. It runs `aether-doctor` and shows a fixed report: the summary, one line per check and the fixes. It changes nothing |
| `help` skill | `/aether:help [topic]`, which sets `disable-model-invocation`. It says what Aether adds, organized by what the person wants to do, with the command of each thing and the guide in their language. It changes nothing |
| `audit` skill | `/aether:audit [topics] [--no-tests]`, which sets `disable-model-invocation`. It audits the project in seven phases: an automated analysis without models, one question about the topics to audit (none when the person names them), read-only reviewer delegates per topic, read-only verifier delegates that try to refute each finding, a cleanup against the open issues and the earlier audit, a triage from P0 to P3, and one list for the person to choose from. It changes nothing in the project, saves the report in the data directory, and creates a GitHub issue only for what the person chooses |
| Launcher | `plugins/aether/launcher/aether-lead`: Claude Code with the Lead as the agent, at `xhigh`, with permissions bypassed, superpowers off, the Aether theme in the session's own settings and `AETHER_IRREVERSIBLE=enforce`. It is outside `bin/` so that it is not on the Bash tool's `PATH`. `scripts/aether-lead` in a clone forwards to it, and the stub of `aether-first-setup` runs it. See [Getting started](../getting-started.md#start) |
| `aether-guard` | A PreToolUse hook. In an Aether session it refuses Write, Edit, MultiEdit and NotebookEdit on specs, plans and tasks (`specs/NNN-<topic>/`, and former superpowers specs and plans) and on the constitution to every agent but the Lead and the Writer, on the autonomy registry and run states to every agent, on Aether skills and downloaded skills to every agent, and on everything outside `.aether/exam/` (and the old `.aether-exam/`) to the Examiner. Before Bash, it records an irreversible command across the eight classes (`merge-main`, `push`, `publish`, `deploy`, `delete`, `credentials`, `paid-call`, `skill-install`) that no grant covers in the owner's list, `.aether/pending.jsonl`, and refuses it when `AETHER_IRREVERSIBLE=enforce`. In any other session it allows everything |
| `aether-autonomy` | The owner's standing authorizations, verified against their own words (`grant`, `revoke`, `check`, `list`), and an autonomous run's state and ceilings (`start`, `spend`, `status`, `end`) |
| `swarm` skill | The Lead's procedure: compile, launch, read the result, report, relaunch, finalize |
| `skills` skill | `aether:skills`: the Lead's procedure for skills (spec 030): the four kinds and their places, finding and installing with `npx skills`, the trusted authors, creating a project or a permanent skill, and giving a task at most 3 skills with `Skills:` and `AETHER-SKILLS:`. It does not set `disable-model-invocation`, so it adds an entry to the skills list |
| `models` skill | `aether:models`: the model index, pricing, ladder models and their makers’ descriptions, and rules for model selection and quota |
| `designing` skill | `aether:designing`: the Lead’s procedure for the intent card, design workflow outcomes, and exam |
| `art-direction` skill | `aether:art-direction`: how the Writer writes the art direction of a visual feature, `art-direction.md` in the feature folder, before the plan (spec 030) |
| `tidy` skill | `aether:tidy`: `/aether:tidy [project or folder]`: reports what it would move or delete in a project, with `aether-doctor tidy`, and changes nothing without the owner's yes (spec 030). It sets `disable-model-invocation`, so it adds no entry to the skills list |
| `aether-plan` | Checks a plan and compiles it into briefs and a dependency graph of waves, and records the run's test baseline. It reads a Spec Kit `tasks.md`, and the `spec.md` beside it. It refuses chain-shaped plans, and waves whose tasks own overlapping files |
| `aether-wt` | Unit worktrees and branches: `ensure`, `diff`, `merge` (ownership check, then the tests; undone if they fail; a cut before the tests finish leaves the unit unverified, and the next merge reruns the tests), `salvage` (commits what a unit that ended without its report left, and writes its package), `save` (commits unsaved work of each unmerged unit of a run on its branch), `adopt` (records a unit the Lead integrated by hand), `remove` (saves unmerged work as a patch), `sweep`, `status` (whether a unit is merged, or unverified because its tests were cut), `ladder` (`aether-wt ladder`, which manages the unit's step on the shared ladder and applies verdicts), `gate` (`aether-wt gate`, which runs test commands and checks touched files against Owns before the supervisor without a model), `stuck`, `stuck-tick`, `stuck-end`, `deliver`, `decline` and `watch` |
| `/aether:design` | The design workflow: from the intent card in `specs/NNN-<topic>/intent.md` to an approved spec, plan and tasks and the exam, with the Writer, the Judge and the Examiner in seat rounds and at most two revisions per document, and one result, `approved`, `clarify`, `dispute` or `failed`. A correction round changes only what the Judge flagged. It needs the Workflow tool |
| `/aether:run` | The workflow: waves, the escalation ladder, the agent budget, the merge queue, the final review (which also flags what is extra), and cleanup in `finally`. A retry after an attempt that ended without its report is a split pass, one sub-attempt per owned file |
| Agents | `implementer`, `supervisor`, `reviewer` (adapted from superpowers' templates, MIT) and `ops` |
| Usage meter and ops | A mod that records every model request of an Aether session: agent, model, tokens and time. It also runs the workflow's own `aether-wt` and `aether-lane` commands itself, without a model, and hands the Lead's delegate tasks to the ladder through `aether-delegate`, which fixes their model and effort (see [Ops without a model](../guide/ops.md) and [Delegates](../guide/delegates.md)). Since 0.12.3 it also declares the `/harnesses` command, a read-only pane of the delegation settings and the quota of each harness (see [the panel](../guide/lanes.md#the-harnesses-panel)). It also declares `/spend`, only in an Aether session, a pane of this session's list-price spend (see [the /spend panel](../guide/lanes.md#the-spend-panel)). In any other session it records and runs nothing, declares no command, and does not offer Aether's agents. The one exception is the fault record of a marker check that itself throws (`observe/faults/<session>-<start>.json`, source `register.marker-check`): the check cannot then tell whether the session is Aether's, and that single failure is written |
| `aether-observe` | Self-observation (see the spec `specs/014-self-observation/`): `hook` is the handler of five hooks (`PostToolUse` of `ScheduleWakeup`, `PostToolUseFailure`, `StopFailure`, `PreCompact` and `SessionEnd`); it acts only in a Lead session, keeps identifiers, classes and counts and never the text of a conversation, prints nothing and always exits 0. `file-issues` is the worker of the automatic issues (spec 020): in the development installation with the `autoissue` option on, a Lead session that ends starts it detached, and it opens on the plugin's repository one GitHub issue per failure, with the cleaned evidence of the reading; in any other case it prints an error and does nothing. Nothing else leaves the machine, and no model is called. |
| `aether-continuity` | The session note (spec 030): one verb per hook, seven in all. `stop`, `precompact`, `postcompact`, `stopfailure` and `sessionend` write the note of the session (the last message, the branch and commit, the compaction summary, the cut and the close) in the project's memory folder and refresh the session's mark; `posttool` and `permission` are the PostToolUse and PermissionRequest sides, which print only what their handlers return (`memoryReminder` against putting state in Claude memory, `treeCheck`, `skillRegistry`, `skillReview` and `skillRepeat`). It acts only in a Lead session and prints nothing there except through those two verbs and the notice of `stop` for delegate results without a verdict. The text of the conversation stays in the note on the owner's machine; the observation store of `aether-observe` keeps no text. Stop warns once per unverdicted attempt, and PostToolUse warns at three own edits or ten reads in a turn. No model is called. |
| `aether-report` | Reports a run's speed, cost and quality (including `quality.ladder` with first-try tasks, rises and gate rejections); `--delegates` reports unverdicted results and the delegate tasks and, step by step of the ladder, how they went; `--spend` reports one session's list-price spend; `finalize` records the run; its seats mode counts the design seats' rounds and who answered them; `price` prices any `claude -p` JSON output. Its reads take in the data directories of every install, each record once (see [Data](../guide/maintenance.md#data)) |
| `aether-audit` | The six verbs of an audit, one JSON line each: `analyze` reads the project without models and fixes nothing; `candidates` applies the entry gate to the reviewers' claims; `verdicts` settles each claim from the verifiers' answers; `clean` merges the findings, drops what an open issue covers and marks each one new or still against the earlier audit; `triage` checks the judgments and orders the list from P0 to P3; `report` renders the eleven sections in Spanish or English and, with `--save`, keeps them in the data directory |
| `aether-session-start` | The command that the SessionStart hook runs four times in one entry: with no flag it does the hook's side effects and prints `Aether mode is active.` with its notes; with `--part k`, for k from 1 to 3, it prints only part k of the bootstrap, and nothing when the bootstrap has fewer parts. Claude Code delivers a hook's output whole only up to 10,000 characters, so each part's whole output, the JSON included, stays within 9,800 (issue #139); each part starts with the same two lines, who the Lead is and `Aether mode bootstrap, part k of n`, with the order to read all n parts before acting, whatever order they arrive in, and the whole `skills/using-aether/SKILL.md` if a part did not arrive, and is cut just before a section heading. It acts only for the Lead: in any other session none of the four prints or writes anything |
| SessionStart hook | In an Aether session: runs on startup, resume, clear, compact and fork; marks the session and passes the `superdelegation`, `harnesses` and `deadlines` options (for the delegates) and the `quotabrake` and `brakepush` options (for the quota brake) to its commands; opens the session note, advises where work was left off and what changed, and cleans; on startup, clear and compact, but not on resume, its part commands inject the bootstrap, and the command with no flag sweeps runs left untouched for 24 hours, keeps a summary of the spend before it deletes the usage files and lane logs of a session id not written to for 30 days (session markers carry no spend, and `unknown.jsonl` and non-id names are deleted with no summary), deletes session markers not written to for 30 days, digests the sessions' observations into the durable summary before that prune and deletes `observe/` events, faults and development fragments not written to for 30 days (see [Self-observation](../guide/observe.md)), and points a new Lead to an open autonomous run. On startup only, it also shows the person a welcome line with the version and `/aether:help` (the hook's `systemMessage`), in Spanish when the locale is Spanish. In any other session it does nothing |

## What Aether adds to a normal session

Today the plugin has the fifteen commands of `bin/`, and they are on the Bash tool's `PATH`; the measurement below, taken at 0.7.0, counted eight.

Measured on Claude Code 2.1.296 with Aether 0.7.0, on 2026-10-09, in a session started without `--agent aether:lead`, against the same session with Aether disabled:
- the first request grows by 431 characters, all in the first message: the `aether:run` and `aether:swarm` entries of the skills list;
- the system prompt and the tools are unchanged;
- `claude plugin details` estimates about 100 tokens always on;
- the commands of `bin/` are on the Bash tool's `PATH`;
- each session start, and each `Write`, `Edit`, `MultiEdit` or `NotebookEdit` call, runs one short `node` process that finds no Aether session and exits.

Nothing is injected, refused, recorded or written. Versions 0.8 to 0.12 were not measured this way. They add four things, read from the plugin and not measured: the entries of the four preset skills (`aether:specify`, `aether:plan`, `aether:tasks` and `aether:constitution`) in the skills list, whose descriptions are 459 characters; the entry of the `aether:autonomous-runs` skill, added in 0.11.0, whose description is 223 characters; the same short `node` process before each `Bash` call; and, since 0.12.0, a mod hook before each `Agent` call that checks the session marker and, in a session that is not Aether's, hands the call on unchanged. Version 0.12.3 adds nothing at the start of a plain session: the `/harnesses` command is declared only in an Aether session, so in any other nothing of the panel is injected, written, recorded or run. The `/spend` command is declared only in an Aether session too, so in any other nothing of it is injected, written, recorded or run. The delegate ladder, which replaced the earlier delegate router, adds nothing at the start of a plain session either: its work is the mod's hooks on `Agent` calls, agent spawns and steps, which check the session marker first and hand the call on unchanged, and `aether-delegate`, one file on the Bash tool's `PATH` that replaces the earlier command and runs only when called. This is read from the plugin, not measured.

Each SessionStart runs four short `node` processes: `aether-session-start` without a flag and its three part commands; outside a Lead session all exit without output or files.

The observation hooks (`PostToolUse` of `ScheduleWakeup`, `PostToolUseFailure`, `StopFailure`, `PreCompact` and `SessionEnd`, all run by `aether-observe hook`) write and print nothing in a session that is not the Lead's, and run one short `node` process only on those five events. In the development installation with the `autoissue` option on, a Lead session that ends also starts one detached `aether-observe file-issues` worker, the only process of the observation that calls GitHub (`gh`); it is started in neither a plain session nor the standard installation, nor with the option off. This is read from the plugin and proved by tests/observe-guarantees.test.js; it is not measured in a real session.

The `setup` skill, the `aether-first-setup` and `aether-doctor` commands and the launcher add nothing at the start of a plain session, and this too is read from the plugin, not measured. The skill sets `disable-model-invocation`, which in Claude Code's documentation keeps a skill's description out of the model's context, so it adds no entry to the skills list; `claude plugin details` still counts about 30 tokens for it, as it does for `using-aether`, which sets the same field. `aether-first-setup` and `aether-doctor` are one more file each on the Bash tool's `PATH` and run only when called, with no hook. The `doctor` and `help` skills set the same field, so they add no entry to the skills list either; this too is read from the plugin, not measured. The launcher is outside `bin/`, so it is not on the `PATH`, and it runs only when the person starts it. The `audit` skill sets the same field, so it too adds no entry to the skills list, runs no hook and adds no command; `aether-audit` is one more file on the Bash tool's `PATH` and runs only when called; this is read from the plugin, not measured.

Version 0.35.0 adds seven hook entries that run `aether-continuity` (Stop, PreCompact, PostCompact, StopFailure, SessionEnd, PostToolUse of Write, Edit, MultiEdit and Bash, and PermissionRequest of the file tools), and SessionStart also runs on fork. In a session that is not the Lead's each one finds no Lead and exits with no output and no file, as tests/dormant-030.test.js proves; measured on 2026-11-07, on Node 22 (Linux/WSL2), a call took a median of 32.9 ms (29.5 to 38.9 ms in 20 runs), so one Write adds about 66 ms of process time and a turn about 33 ms. This is a local measurement, not a real session.

PostToolUse of Write, Edit, MultiEdit, NotebookEdit, Read, Grep, Glob and Bash runs one short `aether-continuity` process per call (about 33 ms on Node 22 on Linux/WSL2), with 0 B stdout and 0 files written when `!isAetherSession`.
