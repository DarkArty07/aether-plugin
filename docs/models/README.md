# Models released since 2026-01

The LLMs our harnesses offer, from Artificial Analysis (AA) figures and the harnesses' own listings, so a session reads files and not an API. The data lives in the plugin, so it ships with it and a session in any project reads it: [`models.json`](../../plugins/aether/config/models/models.json) is the list an orchestrator reads (each model in use with its harness, the id or alias to pass to the CLI, its efforts, its scores and its profile, and the `excluded` models the owner keeps out), [`profiles.json`](../../plugins/aether/config/models/profiles.json) says what each model is for, and [`harness-models.json`](../../plugins/aether/config/models/harness-models.json) holds what each harness's CLI listed, with the day it was captured. This folder has only this page, the reading copy of the list. The first harness is the native one, `claude`: its models are not lanes, so they have no `*` below.

## Refresh

```
node scripts/build-models-index.js --write                  # AA API: ARTIFICIAL_ANALYSIS_API_KEY, or .env in ~/.local/share/aether-plugin
node scripts/build-models-index.js --from raw.json --write  # a saved AA answer, no network
```

It rewrites `models.json` (in `--out`, default `plugins/aether/config/models`) and the generated part below (in `--docs`, default `docs/models`), and exits 1 when a model has no profile. Grouping: an AA slug ending in an effort (`-low`, `-high`, `-max`, `-reasoning`...) joins the slug without it when AA's name names that effort; a date or any other word makes a family of its own.

## Add a harness

1. Capture its listing into `harness-models.json`, with the day (`capturedAt`) and `listedBy`, `effortVia` (`id` when the effort is part of the id, `flag` when it is a flag) and `models`: claude by hand from `claude --help` (its `--model` aliases and its `--effort` levels; Claude Code has no command that lists models), agy `agy models`, grok `grok models`, cursor `cursor-agent --list-models`, codex the `models` of `~/.codex/models_cache.json`, muse the ids the `model/list` method of `muse serve` returns (no CLI command lists them). A model is an id, or, for a harness whose effort is a flag (claude, grok, codex), an object `{id, alias, efforts, listed, excluded}`: `alias` is the name the CLI takes in place of the id, and `excluded` is the reason the owner keeps a listed model out of use (a non-empty string; it goes to the `excluded` list of `models.json`, with its profile, even when the model is also superseded or older than the date). A harness whose effort is in the id (agy, cursor) lists ids as strings only, and the script exits 1 on an object there, on an object with no `id`, and on an `excluded` that is not a non-empty string.
2. Add it to `DEFAULT_HARNESSES` in the script (or try it with `--harnesses claude,agy,grok,codex,muse`); without a listing the script says so. Muse is not in `DEFAULT_HARNESSES` until its listing is captured.
3. Write a profile for each new model in `profiles.json` from its maker's pages, then refresh.

## Rules

1. Only the newest generation of each line is used (Sonnet 5.5, not Sonnet 5); the older ones are superseded.
2. Only a model the CLI of a chosen harness lists is in, whatever Artificial Analysis lists; a model only the lane table names is not offered.
3. Every model has a profile written from its maker's pages, with its sources and the date checked; without one the build exits 1.

## What each is for (`profiles.json`, from the maker's pages)

- **Claude Haiku 5.5** `claude-haiku-5-5` (claude, alias `haiku`), Anthropic: "For high-volume, latency-sensitive tasks such as classification, extraction, and routing." Its model page adds: "built for high-volume, latency-sensitive work such as classification, routing, extraction, and subagent tasks." Comparative latency: fastest. context 1M, output 128K; default effort medium; $0.1 / $0.5 per M; cutoff 2026-06. Claude API id claude-haiku-5-5; released 2026-10-07, not retired before 2027-10-07. Claude API, Amazon Bedrock, Google Cloud, Microsoft Foundry and Claude Platform on AWS. Each harness takes the efforts its entry lists. Adaptive thinking is on by default and effort is its main control; thinking can be disabled only at high effort or below, and a request that disables it at xhigh or max returns a 400 error. At low effort in long agent prompts the model is more likely to skip a search, stop early, or skip a check (Anthropic's effort page): start at medium. Its tokenizer counts the same text as about 30% more tokens than Claude Haiku 4.5. It is the only current Claude model priced by prompt length; the others include the full 1M window at one price. (checked 2026-10-14)
