# Lanes

Superdelegation sends every call that is not the Lead's to another coding plan you pay for, while that plan's quota lasts, and leaves native Claude as the fallback. This page is the rule, written once; the `superdelegation` and `harnesses` options that drive it are in [Options](options.md#options), and the other pages say only what the rule decides and link here.

## Running Aether's calls on other plans

### Lanes

A lane runs one of Aether's own calls on another coding plan the owner pays for. agy, the Antigravity CLI, was the first; Codex, Grok, Cursor and Muse have adapters too. See the [lanes spec](../superpowers/specs/2026-10-08-lanes-design.md), the [superdelegation spec](../../specs/009-superdelegation/spec.md) and phase 2b of the [RADAR roadmap](../roadmap/2026-10-10-radar.md).

- **The switch.** `superdelegation`, off by default, is the only choice (see [Options](options.md#options)). Off, every call of an agent that is not the Lead is native Claude, in the swarm and in the design, whatever the quota. On, each of those calls goes to an external harness whenever a pair satisfies the rule below, and the native agent takes only the call that none can. It runs only on Linux, and `aether-plan compile <plan.md> --no-lanes` turns it off for one run. **Options you set before.** The old `lanes` and `seats` options stay in the manifest only so that a value you saved is not lost silently. If `superdelegation` is not set and `lanes` is on, superdelegation counts as on; if `superdelegation` is set, `lanes` is ignored; `seats` is always ignored, whatever its value, because the three profiles it chose between no longer exist. The session start and `aether-report` tell you which old value was read or ignored.
- **Which harnesses.** The plugin's `harnesses` option lists the harnesses superdelegation may use (`harnesses`, `agy` by default; the names are `agy, codex, grok, cursor, muse`). A harness competes for a call only if it is in the list, its CLI is installed and `plugins/aether/config/pairs.json` has a pair of it. A harness with no pair, such as Codex and Cursor today, takes nothing, and `aether-plan compile` names each enabled harness that takes no call, and why.
- **What a call asks for.** Every call has a reference pair: the Claude pair, model and effort, it would run on natively. In the swarm it is the pair the plan gives the task (or the attempt's, in a retry); in the design it is the pair of the seat's native agent: Opus `high` for the Judge and the Examiner, Sonnet `high` for the Writer. The call asks for the Artificial Analysis intelligence points of that pair, never for a model name: Sonnet `high` asks 46.8 and Sonnet `xhigh` asks 51.9, because an effort is worth what it scores. The pairs and their points, with the cost per task Artificial Analysis measures, are in `plugins/aether/config/pairs.json`, one row per model and effort of each harness. The effort of a pair is the effort it runs at: the rule never turns one effort into another.
- **Who is a candidate.** Any external pair whose points reach what was asked minus 1 point (the tolerance; a pair at exactly the asked minus 1 point is in). A pair with no intelligence or no cost per task in the table is not a candidate, unless the owner decided it enters (`ownerDecision`, Muse alone today). Within one quota, a pair that gives no more than 1 point over a cheaper candidate is never used: Grok `xhigh` (46.4 points, US$ 3.74) does not take a call that Grok `high` (46.3, US$ 2.73) can. A pair of a quota that is dry, of a harness that is not enabled or installed, or that the call excluded does not compete.
- **The order.** The quota whose weekly window renews first goes first: the 5 hour window renews every few hours and would always win, so it only says whether the quota can be used now, and a window that cannot be read goes after the ones that can. Within that quota, the lower cost per task; a pair with no cost per task (Muse's) goes last in its quota. Ties go to more points, then to the order of the table. A harness competes only for the calls its pairs reach: Grok's best pair gives 46.4 points, so it receives nothing from a call that asks 51.9 or more, even when its quota renews first.
- **Speed does not decide.** No pair is chosen or left out for being fast or slow; the report shows how long each call took.
- **Native fallback.** The call runs in the native agent, at its reference pair, and never asks the owner anything, when no pair is a candidate, when every quota that could take it is dry (if one is healthy, the call goes to it), or when the external call fails on every pair that began it (three at most). This is not the end of the ladder: a retry asks the rule again.
- **Nobody reviews its own work.** The model that reviews (the supervisor, the Judge, the Examiner and the reviewer of the final review) is never the model that made what it reviews. A pair of the same model family as the author is not a candidate, also inside another harness; and when the review falls to native, it runs on the Claude model of Haiku, Sonnet and Opus that is not the author, at the same effort as the reference pair, whose points are closest to the ones asked (the stronger on a tie). This rule wins over the fallback above. With superdelegation off, the swarm is as it was and the design seats keep their rule that the model that wrote a document does not review it.
- **A retry.** An attempt after a failure asks for the points of its own reference pair, not the one before it, and does not run on the pair that just failed. A step of the ladder with no external candidate runs native. A spent ladder still blocks the unit (`the ladder is spent`): the rule adds no attempt.
- **No limit on parallel calls.** A harness has no limit on its calls in flight: the owner decided it (A74), because the harnesses have none. A call starts at once on the pair that was chosen, as many as the swarm's own waves and the Lead's delegates launch together. The only limits on a harness are its quota (readings, marks and windows, below) and the swarm's waves.
- **Who takes a call.** `plugins/aether/config/lanes.json` holds, for each harness, how it is run: `waitSeconds`, `quotaLifeMinutes`, `timeouts`, its quota `groups`, and each model with its `group`, `roles` and `aa` figures. The pairs it can take are in `pairs.json`. For agy: Gemini 3.8 Flash at `low`, `medium` and `high`, Gemini 4 Argon at `high`, and agy's own Sonnet 5.5 and Opus 5.5 at `low`, `medium` and `high`; they score the same as the native ones, because Artificial Analysis measured the same model. For Grok: `grok-4.7` at `low`, `high` and `xhigh` (checked against grok 1.0.41 on 2026-10-13; `grok-4.7-build-fast` is the same model faster and at twice the price, so it is not a lane). Codex and Cursor have entries without models: their model ids depend on your account and the CLI's version, so you add them once you have checked them (below). Muse's entry has one, `muse-wonder-full-1.0`, the only model its CLI lists to the owner's account, whose pair scores as Opus `high` by the owner's decision (see [Muse](#muse)). With the table of today, a call that asks 56 points or more (Sonnet `max`, Opus `xhigh`, Opus `max`) runs native, because no external pair reaches 55.
- **Quota.** A group is used while every window of it, such as agy's 5 hours and weekly, stays above a 5% reserve (`reserve` in the table) and no dry mark holds it. A call that ends for quota, or a start that finds the group dry, leaves a dry mark in the plugin's data directory, so it outlives the wave and the run: until the group's reset when a reading with a balance shows the group under the reserve, and otherwise for 60 minutes (`dryMarkMinutes`), renewed if the next call in the group ends for quota again; a fresh reading that shows the group healthy lifts a mark that came from a reading (below). A reading that launches a process, agy's, is kept for its life (`quotaLifeMinutes`: 10 minutes) and served to the starts and to `status`, so they launch none inside it; a finished agy call and `aether-lane quota` take a fresh reading, which renews the kept one. Grok's reading is not kept: its 30 minutes (`quotaLifeMinutes`) are the age after which its log line is stale and `aether-lane pick` refreshes it. Grok's weekly share stays valid until its week ends. Codex and Cursor report no quota, nor does Grok without a reading: each competes after the groups that have one, until a call fails for quota. Muse's is the one its last call reported, and unknown before that call (see [Muse](#muse)). The router uses the same rule for the quota of a read-only delegate (see [Quota](router.md#quota)).
- **agy's quotas and its refusals.** agy has individual quotas that its `/usage` does not show: it lists two groups, `Gemini Models` (Flash and Argon together, since agy 1.4.2) and `Claude and GPT models`, and the table has three keys for agy, `argon`, `flash` and `claude`. `groups` maps each key to the `/usage` group it reads, and several keys may read one group: `argon` and `flash` both read `Gemini Models`, so they show the same windows and the same reset, but each has its own mark, place in the order and choice, and a refusal of Argon does not keep Flash out. What tells that a quota is gone is agy's refusal, `Individual quota reached. ... Resets in 163h22m27s.`: a lane call or a design seat that agy refuses leaves a dry mark on the group of the model it called, whatever `/usage` shows. The mark holds 60 minutes (`dryMarkMinutes`), not the reset the message states: that reset was wrong once (agy refused Argon with "Resets in 163h" and answered three days later) and agy's quotas change between versions, while a refused call costs a failed process and no tokens, so the group is tried again every hour. `aether-lane quota` shows that the mark comes from a refusal, with the reset agy stated as stated. A design seat skips a group a dry mark still holds and goes to the next pair of the rule, or to the native agent. **Marks heal.** A mark that came from a reading is lifted when a fresh reading, taken after the mark and younger than `quotaLifeMinutes`, shows every window above the reserve: a lane call's start, `aether-lane quota` and `status`, the router and a design seat's choice all check it, because providers renew a quota without saying so. A refusal's mark is never lifted by a reading, since `/usage` does not show an individual limit. An unconfirmed mark never holds longer than the minutes it was given, whatever its file says. A mark file of a group the table does not have is ignored.
- **Fallback to the next candidate.** When a harness is missing, out of quota or fails to start, the same call goes to the next candidate, and to Aether's own agent when none is left, without spending the ladder. A lane that fails after it started, or ends for quota, asks for the next pair too, up to three pairs that began the call in all, and goes to the native agent only after the third failure; the final review offers each of its slices (`final-review-slice-<n>`) to the pairs in the same way when none takes the whole package. A call that goes native for any cause is logged with that cause (`chosen`, `no-candidate` or `failed`).
- **Containment.** A lane works without permission prompts in the unit's worktree: agy with `--dangerously-skip-permissions`, Codex in its `workspace-write` sandbox, Grok with `--always-approve`, Cursor with `--force`, Muse with `--disable-approval` and its sandbox on. Git checks catch changes outside the task's Owns, to the integration worktree and branch, and from read-only roles. The lane's environment drops variables named like tokens, keys and secrets, points `gh`, `npm`, `docker`, `gcloud`, `aws` and `kubectl` away from your credentials, and sets git's `protocol.allow` to `never`, so a plain git command in the lane cannot reach a remote. Your home directory stays, because each CLI keeps its own login there. So this prevents accidents, not an agent that overrides these settings or goes looking for your files. Nothing undoes a network action, so you turn on each harness yourself.
- **Report.** `aether-report` shows, per call, its reference pair, the pair that took it, why, and how long it took; and, for the run, the share of the work that left Claude, the quota used per harness, and the dollars at list price, apart from native Claude. It also shows, per group, its calls, the share left of each window at the start and at the end of the run and the next reset, and says which old option values were ignored or reinterpreted (`lanes.run.choices` holds what every call chose: the candidates in order and the reason). The same choices are in the lane log, one `choice` entry per call and one `took` entry when the call ends. `aether-lane status <run>` gives, per group, what `aether-lane quota` does plus its dry mark, and `aether-lane pick` prints the decision of one call.
- **Off by default.** Nothing leaves Claude until you turn `superdelegation` on yourself (see [Options](options.md#options)), because a lane works without permission prompts and spends the quota of another plan.
- **Linux only.** Lanes need Linux, because stopping a lane's processes reads `/proc`.

**Reading the quota.** `aether-lane quota [<harness>...] [--refresh] [--json]` needs no run. For each harness, by default the installed ones, it prints each group's windows: the share left, the reset in UTC and local time, the hours left, the priority, whether the group is usable above the reserve and with no dry mark, and where the reading came from and how old it is. agy's reading is its `/usage`. **Grok's quota is read over ACP**: grok answers the request `_x.ai/billing` on `grok agent stdio` with the config its UI logs as `billing: fetched credits config` (about a second, no UI, no session and no model call), and the request also leaves that line in `~/.grok/logs/unified.jsonl`, where `status` and `start` read it; they call it stale after 30 minutes. `aether-lane quota --refresh`, and `aether-lane status <run> --refresh`, the quota step of each wave in the workflow, ask grok over ACP (10 seconds at most); if that gives no answer, an error or no config, the fallback opens grok's UI for a few seconds (20 at most) in an empty temporary directory, with no prompt, and removes the session folder grok made for that directory, and no other. A `status` run by hand does not refresh. A line without `creditUsagePercent` is read as 0% used, and says so wherever it is shown (spec 002, A3). Aether never refreshes inside a lane call.

**Adding a harness.** A harness is an adapter, `plugins/aether/lib/harness/<name>.js`, an entry in the lane table and its pairs in `plugins/aether/config/pairs.json`, and its name goes in `HARNESS_NAMES` and `FACTORY` of `plugins/aether/lib/harness/index.js`, or the `harnesses` option drops it; the rule does not change. A model of the lane table has a `group` (its quota), `roles` and `aa` (its Artificial Analysis figures and slug); there is no table of equivalences to Claude's models, because a pair is worth the points it scores. The adapter's `quota()` gives, per group, its windows (`remaining` from 0 to 1 and `resetsAt`) or `unknown` when it cannot read them, which puts the harness's quota after the ones with a reading. An adapter whose reading launches a process sets `quotaCost: 'process'`, and Aether keeps the reading for `quotaLifeMinutes`.

**Turning on Codex, Grok, Cursor or Muse.** Their adapters follow Spec Kit's command lines. Grok's was checked with real headless calls on 2026-10-13 (its JSON fields and `--reasoning-effort`; it takes no `--json-schema`, so the schema goes in the prompt); Codex's and Cursor's have run no real call yet, and Muse's was checked with real calls on 2026-10-19 (see [Muse](#muse)). Grok's model, `grok-4.7`, and Muse's, `muse-wonder-full-1.0`, are already in the lane table, so they need only step 3. For Codex and Cursor:
1. find its models in the CLI's own list, and make one real headless call per role with the command line of its adapter (`plugins/aether/lib/harness/<name>.js`); correct the adapter's field names if the CLI's JSON differs;
2. copy `plugins/aether/config/lanes.json` and `plugins/aether/config/pairs.json`, add the models to the harness's entry in the first, each with `group`, `roles` and `aa` like agy's, and one pair per model and effort to the second, with the intelligence and the cost per task Artificial Analysis gives for it (`scripts/refresh-lanes.js` refreshes the points by the pair's slug); set `AETHER_LANES_CONFIG` and `AETHER_PAIRS_CONFIG` to the copies in the shell that starts Claude Code. Codex, Grok and Muse take the effort of the pair as their reasoning effort; Cursor ignores it for now;
3. add the harness to the `harnesses` option, such as `agy,codex`, and turn `superdelegation` on.

### Delegates that edit

With superdelegation on, a delegate task that edits files goes first through `aether-lane delegate --brief <file> --model <model> --effort <effort> --owns <globs> [--tests <command>]`. It runs in a unit worktree and never in the owner's checkout. A pair that fails saves its patch and passes to the next candidate. When no candidate is found, it reports `no-candidate` with a run id and falls back to Claude. It brings back the summary, the branch, the test results, and a review of the diff from a distinct pair, and the Lead merges the branch with `aether-wt merge`.

### The /harnesses panel

`/harnesses` opens a pane inside Claude Code that shows the delegation settings and the quota of each harness, so you do not have to run `aether-lane quota` by hand. It prints nothing to the transcript, calls no model and works even while the Lead is in the middle of a turn. `Esc` or `x` closes it, and `r` renews the readings. It is read-only: it changes no setting and has no toggle button, because the switch for lanes is the `superdelegation` option, in `/plugin configure aether@aether-plugin` or `/config`.

**Only in an Aether session.** The command exists only in a session started with `aether-lead` (agent `aether:lead`). In any other session it is not offered and nothing of it runs, so a plain session is as it was (see [what Aether adds to a normal session](../reference/components.md#what-aether-adds-to-a-normal-session)). The panel uses Claude Code's plugin UI API for mods, which is early access: its surface may change between Claude Code releases without notice, and if it stops working the panel simply does not draw. Nothing else of Aether depends on it. It was checked on Claude Code 2.1.302.

**What it shows**, from top to bottom:
- the title, `Aether · other harnesses`, and the options line, `superdelegation ON|OFF · router <mode> · decider <x> · harnesses <list>`. These are the values the session really uses, with the same validation and fallbacks as the libs: an unknown router mode is `record`, an unknown decider is `haiku`, unknown harness names are dropped and an empty list is `agy`. With superdelegation off, it says that nothing leaves Claude;
- the buttons `Renew readings` (`r`) and `Close` (`x`);
- for each harness (agy, grok, codex, cursor and muse), its version; `not enabled` when it is installed but not in `harnesses`, and `enabled, not installed` when it is listed but missing. For each quota group it gives the label and a status, `usable`, `dry until <date> UTC` (from the group's mark), `under the reserve` or `no reading`, and for each window (`weekly`, `5h`) a bar, the share left and `resets in <h>`, with how old the reading is and `stale` when it is;
- `Recent delegates`: the five newest delegations of the router log in the last 7 days, from any session, each with its age, the `harness/model/effort` it ran on, the task's description, and a mark when the router fell back. See [Delegate router](router.md#delegate-router).

Colours follow your theme: green for usable or enough, amber for low, dry, not enabled or stale, red for under the reserve, and dim for the rest.

**Layout.** From 110 columns in Claude Code's fullscreen layout the pane docks to the right of the transcript (about 67 columns wide at 150); below that, or on the main-screen layout, it sits above the prompt. It fits the room it has: when the full layout does not fit, it drops detail in steps and always keeps the title, the options line, the buttons and one line per enabled harness group. The arrow keys scroll the rest while the pane has the keyboard.

**Where the numbers come from, and how fresh they are.** The panel runs `aether-lane quota --json <harness>` once per harness, in parallel, so a slow agy does not hold back Grok (agy's reading launches `agy -p /usage` and takes 5 to 8 seconds; Grok's takes about a second), and `aether-report --delegates` with `--since` set to seven days ago. `r` reads the quota again with `--refresh` (Grok over ACP, agy's `/usage`); neither is a model call, and opening the pane costs no model tokens. After the first reads, a Grok reading older than 30 minutes is renewed once by itself.

**Safety.** Any text from a CLI or from a delegate's description is stripped of control characters and bidi overrides before it is drawn, because Claude Code refuses to draw a pane that holds a control character, and widths are measured in terminal cells. [Troubleshooting](troubleshooting.md#the-harnesses-panel-is-not-offered) covers a panel that is missing, cut or showing `Quota unavailable`. The sessions it was tried in are listed in [the handoff](../handoff/2026-10-17-harness-panel-0.12.3.md).

### The /spend panel

`/spend` opens a pane with the list-price spend of this session. It exists only in an Aether session, the one started with the agent `aether:lead`. It calls no model and writes nothing to the transcript, including while the figure is still being read, and `Esc` or `x` closes it. From the shell the same figure is `aether-report --spend [--session <id>]`. The panel always passes this session's id. Without `--session`, the command reports the session that wrote last.

The dollars are list price, not a percentage of the quota and not what a subscription charges. The total is the Lead's turns and the agents', split by model, by effort and by role, plus the calls to other harnesses and their dollars.

The same id keeps adding when you resume it: `/resume`, `/compact`, or closing the session and coming back. Another id is not linked to the one before it. `--fork-session` and `/clear` each start a new id, and the earlier one stays its own session.

A model with no price is listed and is not added to the total. The count of resumptions is approximate. A resumption is a gap of more than an hour between two consecutive events of that id, the pane labels the count `approximate`, and after a prune the gap between the archived stretch and what is still on disk is not counted. When part of the record could not be read, the total is what was read and the figure says `incomplete`. With no record the pane says `No spend recorded yet`. It does not show a total of US$ 0.00, and it does not show another session.

[Troubleshooting](troubleshooting.md#the-harnesses-panel-is-not-offered) covers a `/spend` that is not offered, for the same reason as `/harnesses`. The ceiling of an autonomous run is another figure, and it still leaves out the Lead's own turns ([Autonomy](autonomy.md#autonomy-1)).

## Muse

Muse Code is Meta's coding agent, the `muse` CLI. It is the fifth lane harness, last in the `harnesses` list (`agy, codex, grok, cursor, muse`), and superdelegation sends it calls by the same rule, order and reserve as the others (see Parallel and models below). What follows is what the adapter does; the design is in [spec 008](../../specs/008-muse-harness/spec.md) and the Muse decision in [decisions](../decisions.md).

- **How a call runs.** In the unit's worktree, Aether runs `muse exec --json --provider meta --model <model>`, with `--reasoning-effort` set to the effort of the pair that took the call, and `--output-schema` when the role asks for a structured answer. The call takes no standard input and asks nobody for anything: `--disable-approval`, `--disable-request-user-input` and `--disable-reminders` are on, and the run stops after 200 model steps. The reply, the failure reason and the token usage are read from the JSON records, and they come back as those of any other harness.
- **The sandbox stays on.** `--disable-approval` takes away only Muse's approvals. Muse's own sandbox runs the commands, and the workspace is not trusted, so Muse loads no project rules and starts no subagents on its own. The call carries none of `--yolo`, `--disable-sandbox`, `--trust-workspace` or `--api-key-stdin`. If the sandbox does not start, the call fails and the unit runs on the native agent; Aether never repeats it with the sandbox off.
- **Privacy.** Contributor mode is off on every call (`--contributor-mode off`) and no option turns it on, because Meta trains on the content of a run when it is on. A model whose id ends in `-contributor` is never put in the table nor called. `--no-foreign-personal-context` keeps Muse from loading rules, skills and memories that you keep for other tools.
- **Account.** Aether does not sign in for you: it never runs `muse login`, never opens Muse's credential files and does not use `META_API_KEY` (a lane's environment drops variables with `KEY`, `TOKEN` or `SECRET` in their name, and this harness is meant for your subscription, not a per-token key). Sign in to Muse yourself, once, in your own terminal.
- **Quota.** Aether does not read Muse's quota before a call. It knows it from what Muse reported at the end of its last call: the 5 hour window and the weekly one, kept in `lanes/quota/muse-observed.json` in the plugin's data directory. Before the first call the quota is unknown, which counts as usable and puts Muse after the groups that have a reading. A failure that carries Muse's own quota datum (never the text of the message) leaves the same 60-minute dry mark as the other harnesses (`dryMarkMinutes`), and a healthy observation from a later call lifts it.
- **Fallback.** Every failure sends the call to the native agent, in its reference pair, without asking you: Muse not installed, `authRequired`, quota spent (only when the failure carries Muse's own quota datum), an `environmentError` from the sandbox, a timeout, `stepLimit`, a model your account does not give (`modelError`), output that cannot be read or lacks the object asked for, and any other non-zero exit. An `environmentError` leaves no mark and the quota is not counted as spent, so the next unit sent to Muse tries the sandbox again.
- **Parallel and models.** Muse has no limit on parallel calls: two `muse exec` in different worktrees ran at once on 2026-10-19 and both came back clean. The lane table has one model, `muse-wonder-full-1.0`, the only one the CLI lists to the owner's account (`model/list` of `muse serve`), which Meta gives only on the Power and Maximum plans; an account without the plan is refused and the call runs native. It enters the rule **by the owner's decision**: Artificial Analysis names an effort for its only figure of this model, `max` (55.8 in intelligence), which the CLI does not take (it goes up to `xhigh`), so the table could not score it at an effort it runs. The entry carries the owner's words in `ownerDecision`, and `plugins/aether/config/pairs.json` has the pair `muse/muse-wonder-full-1.0@high` scored as Opus `high` by that decision: 53.6 points and no cost per task. With no cost it goes last in its quota, and it takes the calls that ask up to 54.6 points, down to Opus `high`, and not those of Opus `xhigh`, Sonnet `max` or Opus `max`. Its pair runs at `high`, the effort the CLI was tried at, and the rule does not turn any other effort into it. `muse-spark-1.3` also answered a real call, but the CLI does not list it to this account, so it is not in the table. Add `muse` to `harnesses` and, with `superdelegation` on, it competes for calls; `scripts/lane-smoke.js muse` calls it with the table's model, or the one you name, and spends quota, so run it on purpose.
- **Seen in real calls (2026-10-19, muse 1.4.11).** A clean call takes 5 to 12 seconds and about 54,000 input tokens for a one-line task, most of it Muse's own instructions. `allowance` arrives in the usage record in snake_case, with a `window` and a `weekly` block (`used_percent`, `resets_at_ms`) and no tier, and the quota the adapter keeps from it reads as the 5 hour window and the weekly one. `--output-schema` takes the roles' schemas, the sandbox runs inside WSL2, the subscription covers `muse exec`, and tool calls appear in the JSON records. Not seen: a failure in the middle of a run. Muse's own `--max-model-steps 1` did not give one: the run never ended and the lane's time limit killed it (the adapter passes 200).
