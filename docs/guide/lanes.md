# Lanes

Superdelegation sends every call that is not the Lead's to another coding plan you pay for, while that plan's quota lasts, and leaves native Claude as the fallback. This page is the rule, written once; the `superdelegation` and `harnesses` options that drive it are in [Options](options.md#options), and the other pages say only what the rule decides and link here.

## Running Aether's calls on other plans

### Lanes

A lane runs one of Aether's own calls on another coding plan the owner pays for. agy, the Antigravity CLI, was the first; Codex, Grok, Cursor and Muse have adapters too. See the lanes spec, the [superdelegation spec](../../specs/009-superdelegation/spec.md) and phase 2b of the RADAR roadmap.

- **The switch.** `superdelegation`, off by default, is the only choice (see [Options](options.md#options)). Off, every call of an agent that is not the Lead is native Claude, in the swarm and in the design, whatever the quota. On, each of those calls goes to an external harness whenever a pair satisfies the rule below, and the native agent takes only the call that none can. It runs only on Linux, and `aether-plan compile <plan.md> --no-lanes` turns it off for one run. **Options you set before.** Earlier releases read the old options: If `superdelegation` is not set and `lanes` is on, superdelegation counts as on; if `superdelegation` is set, `lanes` is ignored; `seats` is always ignored, whatever its value, because the three profiles it chose between no longer exist. This release reads only `superdelegation`: `resolveOption` in `plugins/aether/lib/superdelegation.js` turns it on only when the value is `true`, and a saved `lanes` or `seats` value is not read.
- **Which harnesses.** The plugin's `harnesses` option lists the harnesses superdelegation may use (`harnesses`, `agy` by default; the names are `agy, codex, grok, cursor, muse`). A harness competes for a call only if it is in the list, its CLI is installed and `plugins/aether/config/pairs.json` has a pair of it. A harness with no pair, such as Cursor today, takes nothing, and `aether-plan compile` names each enabled harness that takes no call, and why.
- **What a call asks for.** Every call has a reference pair: the Claude pair, model and effort, it would run on natively. In the swarm it is the pair the plan gives the task (or the attempt's, in a retry); in the design it is the pair of the seat's native agent: Opus `high` for the Judge and the Examiner, Sonnet `high` for the Writer. The call asks for the Artificial Analysis intelligence points of that pair, never for a model name: Sonnet `high` asks 41.1 and Sonnet `xhigh` asks 49.6, because an effort is worth what it scores. The pairs and their points, with the cost per task Artificial Analysis measures, are in `plugins/aether/config/pairs.json`, one row per model and effort of each harness. The effort of a pair is the effort it runs at: the rule never turns one effort into another.
- **Who is a candidate.** Any external pair whose points reach what was asked minus 1 point (the tolerance; a pair at exactly the asked minus 1 point is in). A pair with no intelligence or no cost per task in the table is not a candidate, unless the owner decided it enters (`ownerDecision`, Muse alone today). Within one quota, a pair that gives no more than 1 point over a cheaper candidate is never used: Grok `xhigh` (34.3 points, US$ 7.512) does not take a call that Grok `high` (35, US$ 6.184) can. A pair of a quota that is dry, of a harness that is not enabled or installed, or that the call excluded does not compete.
- **The order.** The quota whose weekly window renews first goes first: the 5 hour window renews every few hours and would always win, so it only says whether the quota can be used now, and a window that cannot be read goes after the ones that can. Within that quota, the lower cost per task; a pair with no cost per task (Muse's) goes last in its quota. Ties go to more points, then to the order of the table. A harness competes only for the calls its pairs reach: Grok's best pair gives 35 points, so it receives nothing from a call that asks 41.1 or more, even when its quota renews first.
- **Speed does not decide.** No pair is chosen or left out for being fast or slow; the report shows how long each call took.
- **Native fallback.** The call runs in the native agent, at its reference pair, and never asks the owner anything, when no pair is a candidate, when every quota that could take it is dry (if one is healthy, the call goes to it), or when the external call fails on every pair that began it (three at most). This is not the end of the ladder: a retry asks the rule again.
- **Nobody reviews its own work.** The swarm's supervisors, its final review and `aether-lane delegate` keep it as a bar: a pair of the same model family as the author is not a candidate, also inside another harness. The design seats (the Judge, and the Examiner against the plan's author) use that family as a reserve. A pair of another family comes first, then a pair of the author's own family, and the native agent only last. The points a seat asks do not change. When the answer comes from the author's own family, the round's note says that the same family that wrote the document judged it, because no other external pair could. Before a Writer round, when the only external pair that reaches the Judge is the one the Writer would take, that pair is left out of the Writer's candidates, unless leaving it out would leave the Writer with no other external pair. When a review falls to native, it runs on the Claude model of Haiku, Sonnet and Opus that is not the author, at the same effort as the reference pair, whose points are closest to the ones asked (the stronger on a tie). This rule wins over the fallback above. With superdelegation off, the swarm is as it was and the design seats are their native agents.
- **A retry.** An attempt after a failure asks for the points of its own reference pair, not the one before it, and does not run on the pair that just failed. A step of the ladder with no external candidate runs native. A spent ladder still blocks the unit (`the ladder is spent`): the rule adds no attempt. A retry after an attempt that ended without its report, when the task has two or more owned files, is one split pass: the pass asks for one pair and every sub-attempt uses it. A failure of that pair during the pass ends the pass, and the next attempt asks again without that pair.
- **No limit on parallel calls.** A harness has no limit on its calls in flight: the owner decided it (A74), because the harnesses have none. A call starts at once on the pair that was chosen, as many as the swarm's own waves and the Lead's delegates launch together. The only limits on a harness are its quota (readings, marks and windows, below) and the swarm's waves.
- **Who takes a call.** An external model takes a call only when the lane table lists the call's role in that model's `roles`; when no external model lists the role, the native pair takes the call (`allowsRole` in `plugins/aether/lib/superdelegation.js`). `plugins/aether/config/lanes.json` holds, for each harness, how it is run: `waitSeconds`, `quotaLifeMinutes`, `timeouts`, its quota `groups`, and each model with its `group`, `roles` and `aa` figures. The pairs it can take are in `pairs.json`. For agy: Gemini 3.8 Flash at `low`, `medium` and `high`, Gemini 4 Argon at `high`, and agy's own Sonnet 5.5 and Opus 5.5 at `low`, `medium` and `high`; they score the same as the native ones, because Artificial Analysis measured the same model. For Grok: `grok-4.7` at `low`, `high` and `xhigh` (checked against grok 1.0.41 on 2026-10-13; `grok-4.7-build-fast` is the same model faster and at twice the price, so it is not a lane). Codex has three models, GPT-6.1 Sol, GPT-6.1 Terra and GPT-6 Luna, each at `low`, `medium`, `high`, `xhigh` and `max` (see [Codex](#codex)). Cursor has an entry without models: its model ids depend on your account and the CLI's version, so you add them once you have checked them (below). Muse's entry has one, `muse-wonder-full-1.0`, the only model its CLI lists to the owner's account, whose pair scores as Opus `high` by the owner's decision (see [Muse](#muse)). With the table refreshed on 2026-10-30, a call that asks more than 55.5 points runs native, because Sol `max` at 54.5 is the highest external pair and the tolerance is one point. Opus `xhigh` (57) and Opus `max` (58.4) are in that set. Sonnet `max`, at 54.2, is within Sol `max`.
- **Quota.** A group is used while every window of it, such as agy's 5 hours and weekly, stays above a 5% reserve (`reserve` in the table) and no dry mark holds it. A call that ends for quota, or a start that finds the group dry, leaves a dry mark in the plugin's data directory, so it outlives the wave and the run: until the group's reset when a reading with a balance shows the group under the reserve, and otherwise for 60 minutes (`dryMarkMinutes`), renewed if the next call in the group ends for quota again; a fresh reading that shows the group healthy lifts a mark that came from a reading (below). A reading that launches a process, agy's, is kept for its life (`quotaLifeMinutes`: 10 minutes) and served to the starts and to `status`, so they launch none inside it; a finished agy call and `aether-lane quota` take a fresh reading, which renews the kept one. Grok's reading is not kept: its 30 minutes (`quotaLifeMinutes`) are the age after which its log line is stale and `aether-lane pick` refreshes it. Grok's weekly share stays valid until its week ends. Cursor reports no quota, nor does Grok without a reading: each competes after the groups that have one, until a call fails for quota. Codex's quota is read before the call (see [Codex](#codex)). Muse's is the one its last call reported, renewed by one minimal call when stale, and unknown before that call (see [Muse](#muse)). A delegate task asks the same rule for the pair of its step (see [The pair of a step](delegates.md#the-pair-of-a-step)).
- **agy's quotas and its refusals.** agy has individual quotas that its `/usage` does not show: it lists two groups, `Gemini Models` (Flash and Argon together, since agy 1.4.2) and `Claude and GPT models`, and the table has three keys for agy, `argon`, `flash` and `claude`. `groups` maps each key to the `/usage` group it reads, and several keys may read one group: `argon` and `flash` both read `Gemini Models`, so they show the same windows and the same reset, but each has its own mark, place in the order and choice, and a refusal of Argon does not keep Flash out. What tells that a quota is gone is agy's refusal, `Individual quota reached. ... Resets in 163h22m27s.`: a lane call or a design seat that agy refuses leaves a dry mark on the group of the model it called, whatever `/usage` shows. The mark holds 60 minutes (`dryMarkMinutes`), not the reset the message states: that reset was wrong once (agy refused Argon with "Resets in 163h" and answered three days later) and agy's quotas change between versions, while a refused call costs a failed process and no tokens, so the group is tried again every hour. `aether-lane quota` shows that the mark comes from a refusal, with the reset agy stated as stated. A design seat skips a group a dry mark still holds and goes to the next pair of the rule, or to the native agent. **Marks heal.** A mark that came from a reading is lifted when a fresh reading, taken after the mark and younger than `quotaLifeMinutes`, shows every window above the reserve: a lane call's start, `aether-lane quota` and `status`, the pair of a delegate task and a design seat's choice all check it, because providers renew a quota without saying so. A refusal's mark is never lifted by a reading, since `/usage` does not show an individual limit. An unconfirmed mark never holds longer than the minutes it was given, whatever its file says. A mark file of a group the table does not have is ignored.
- **Fallback to the next candidate.** When a harness is missing, out of quota or fails to start, the same call goes to the next candidate, and to Aether's own agent when none is left, without spending the ladder. A lane that fails after it started, or ends for quota, asks for the next pair too, up to three pairs that began the call in all, and goes to the native agent only after the third failure; the final review offers each of its slices (`final-review-slice-<n>`) to the pairs in the same way when none takes the whole package. A call that goes native for any cause is logged with that cause (`chosen`, `no-candidate` or `failed`).
- **Containment.** A lane works without permission prompts in the unit's worktree: agy with `--dangerously-skip-permissions`, Codex in its `workspace-write` sandbox, Grok with `--always-approve`, Cursor with `--force`, Muse with `--disable-approval` and its sandbox on. Git checks catch changes outside the task's Owns, to the integration worktree and branch, and from read-only roles. The lane's environment drops variables named like tokens, keys and secrets, points `gh`, `npm`, `docker`, `gcloud`, `aws` and `kubectl` away from your credentials, and sets git's `protocol.allow` to `never`, so a plain git command in the lane cannot reach a remote. Your home directory stays, because each CLI keeps its own login there. So this prevents accidents, not an agent that overrides these settings or goes looking for your files. Nothing undoes a network action, so you turn on each harness yourself.
- **Report.** `aether-report` shows, per call, its reference pair, the pair that took it, why, and how long it took; and, for the run, the share of the work that left Claude, the quota used per harness, and the dollars at list price, apart from native Claude. It also shows, per group, its calls, the share left of each window at the start and at the end of the run and the next reset. `lanes.run.choices` holds what every call chose: the candidates in order and the reason. The same choices are in the lane log, one `choice` entry per call and one `took` entry when the call ends. `aether-lane status <run>` gives, per group, what `aether-lane quota` does plus its dry mark, and `aether-lane pick` prints the decision of one call.
- **Off by default.** Nothing leaves Claude until you turn `superdelegation` on yourself (see [Options](options.md#options)), because a lane works without permission prompts and spends the quota of another plan.
- **Linux only.** Lanes need Linux, because stopping a lane's processes reads `/proc`.

**Reading the quota.** `aether-lane quota [<harness>...] [--refresh] [--json]` needs no run. For each harness, by default the installed ones, it prints each group's windows: the share left, the reset in UTC and local time, the hours left, the priority, whether the group is usable above the reserve and with no dry mark, and where the reading came from and how old it is. agy's reading is its `/usage`. **Grok's quota is read over ACP**: grok answers the request `_x.ai/billing` on `grok agent stdio` with the config its UI logs as `billing: fetched credits config` (about a second, no UI, no session and no model call), and the request also leaves that line in `~/.grok/logs/unified.jsonl`, where `status` and `start` read it; they call it stale after 30 minutes. `aether-lane quota --refresh`, and `aether-lane status <run> --refresh`, the quota step of each wave in the workflow, ask grok over ACP (10 seconds at most); if that gives no answer, an error or no config, the fallback opens grok's UI for a few seconds (20 at most) in an empty temporary directory, with no prompt, and removes the session folder grok made for that directory, and no other. A `status` run by hand does not refresh. A line without `creditUsagePercent` is read as 0% used, and says so wherever it is shown (spec 002, A3). Aether never refreshes inside a lane call.

**Adding a harness.** A harness is an adapter, `plugins/aether/lib/harness/<name>.js`, an entry in the lane table and its pairs in `plugins/aether/config/pairs.json`, and its name goes in `HARNESS_NAMES` and `FACTORY` of `plugins/aether/lib/harness/index.js`, or the `harnesses` option drops it; the rule does not change. A model of the lane table has a `group` (its quota), `roles` and `aa` (its Artificial Analysis figures and slug); there is no table of equivalences to Claude's models, because a pair is worth the points it scores. The adapter's `quota()` gives, per group, its windows (`remaining` from 0 to 1 and `resetsAt`) or `unknown` when it cannot read them, which puts the harness's quota after the ones with a reading. An adapter whose reading launches a process sets `quotaCost: 'process'`, and Aether keeps the reading for `quotaLifeMinutes`.

**Turning on Grok, Cursor or Muse.** Cursor is not tested with a real account. Its adapter follows Spec Kit's command line. Grok's was checked with real headless calls on 2026-10-13 (its JSON fields and `--reasoning-effort`; it takes no `--json-schema`, so the schema goes in the prompt); Cursor's has run no real call yet, and Muse's was checked with real calls on 2026-10-19 (see [Muse](#muse)). Codex is a work harness like the others: its three models and their pairs are already in the lane table (see [Codex](#codex)). Grok's model, `grok-4.7`, and Muse's, `muse-wonder-full-1.0`, are already in the lane table, so they need only step 3. For Cursor:
1. find its models in the CLI's own list, and make one real headless call per role with the command line of its adapter (`plugins/aether/lib/harness/<name>.js`); correct the adapter's field names if the CLI's JSON differs;
2. copy `plugins/aether/config/lanes.json` and `plugins/aether/config/pairs.json`, add the models to the harness's entry in the first, each with `group`, `roles` and `aa` like agy's, and one pair per model and effort to the second, with the intelligence and the cost per task Artificial Analysis gives for it (`scripts/refresh-lanes.js` refreshes the points by the pair's slug); set `AETHER_LANES_CONFIG` and `AETHER_PAIRS_CONFIG` to the copies in the shell that starts Claude Code. Codex, Grok and Muse take the effort of the pair as their reasoning effort; Cursor ignores it for now;
3. add the harness to the `harnesses` option, such as `agy,codex`, and turn `superdelegation` on.

### Delegates that edit

With superdelegation on, a delegate task that edits files goes first through `aether-lane delegate --brief <file> --model <model> --effort <effort> --owns <globs> [--tests <command>]`. It runs in a unit worktree and never in the owner's checkout. A pair that fails saves its patch and passes to the next candidate. When that pair had started and left a patch, the next pair's worktree receives it before the pair starts, and the prompt tells it that an earlier agent began the task. Its uncommitted work, if any, is in the worktree. Continue from it. The patch is applied only when `git apply --check` accepts it and every path it touches is inside `--owns`. Git names the paths it would write, a rename or a copy counts its source as well, and a patch git cannot list is not carried. The check runs at the top of the repository against the run's integration branch, and again in the new worktree. If it does not pass, or the two checks disagree, the next pair gets a clean worktree and the result says why the earlier work was not carried over. The result says for each attempt whether it started from the earlier work. Every failed attempt's patch stays saved. The patch of a later failure is the worktree as that attempt left it, including what it continued from, so the pair after it continues from that latest state and the patches are never stacked. When no candidate is found, it reports `no-candidate` with a run id and falls back to Claude. It brings back the summary, the branch, the test results, and a review of the diff from a distinct pair, and the Lead merges the branch with `aether-wt merge`.

The Lead does not run this command. It launches the delegate task with `Agent`, and the system runs the command for the call, so that the task shows as an agent at work while it lasts, however long the pair takes (see [Delegates](delegates.md#how-a-delegate-runs)). For a correction or a rise of the delegate ladder the command also takes `--pair <pair id>`, the pair that must try first, `--carry <patch file>`, the earlier work, and `--findings <file>`, the findings to fix.

### The /harnesses panel

`/harnesses` opens a pane inside Claude Code that shows the delegation settings and the quota of each harness, so you do not have to run `aether-lane quota` by hand. It prints nothing to the transcript, calls no model and works even while the Lead is in the middle of a turn. `Esc` or `x` closes it, and `r` renews the readings. It is read-only: it changes no setting and has no toggle button, because the switch for lanes is the `superdelegation` option, in `/plugin configure aether@aether-plugin` or `/config`.

**Only in an Aether session.** The command exists only in a session started with `aether-lead` (agent `aether:lead`). In any other session it is not offered and nothing of it runs, so a plain session is as it was (see [what Aether adds to a normal session](../reference/components.md#what-aether-adds-to-a-normal-session)). The panel uses Claude Code's plugin UI API for mods, which is early access: its surface may change between Claude Code releases without notice, and if it stops working the panel simply does not draw. Nothing else of Aether depends on it. It was checked on Claude Code 2.1.302.

**What it shows**, from top to bottom:
- the title, `Aether · other harnesses`, and the options line, `superdelegation ON|OFF · harnesses <list>`. These are the values the session really uses, with the same validation and fallbacks as the libs: unknown harness names are dropped and an empty list is `agy`. With superdelegation off, it says that nothing leaves Claude;
- the buttons `Renew readings` (`r`) and `Close` (`x`);
- for each harness (agy, codex, grok, cursor and muse), its version; `not enabled` when it is installed but not in `harnesses`, and `enabled, not installed` when it is listed but missing. For each quota group it gives the label and a status, `usable`, `dry until <date> UTC` (from the group's mark), `under the reserve` or `no reading`, and for each window (`weekly`, `5h`) a bar, the share left and `resets in <h>`, with how old the reading is and `stale` when it is;
- `Recent delegates`: the five newest delegations of the delegate log in the last 7 days, from any session, each with its age, the `harness/model/effort` it ran on, the task's description, and a mark when an attempt on another harness failed and the task ran on Claude. See [Delegates](delegates.md#reading-the-log).

Colours follow your theme: green for usable or enough, amber for low, dry, not enabled or stale, red for under the reserve, and dim for the rest.

**Layout.** From 110 columns in Claude Code's fullscreen layout the pane docks to the right of the transcript (about 67 columns wide at 150); below that, or on the main-screen layout, it sits above the prompt. It fits the room it has: when the full layout does not fit, it drops detail in steps and always keeps the title, the options line, the buttons and one line per enabled harness group. The arrow keys scroll the rest while the pane has the keyboard.

**Where the numbers come from, and how fresh they are.** The panel runs `aether-lane quota --json <harness>` once per harness, in parallel, so a slow agy does not hold back Grok (agy's reading launches `agy -p /usage` and takes 5 to 8 seconds; Grok's takes about a second), and `aether-report --delegates` with `--since` set to seven days ago. `r` reads the quota again with `--refresh` (Grok over ACP, agy's `/usage`; neither is a model call, and opening the pane costs no model tokens). Muse has no free reading, so with Muse enabled `r` makes one minimal call to Muse Spark 1.3, about 54,000 input tokens of its subscription, and repeated presses repeat that spend. After the first reads, a Grok reading older than 30 minutes is renewed once by itself.

**Safety.** Any text from a CLI or from a delegate's description is stripped of control characters and bidi overrides before it is drawn, because Claude Code refuses to draw a pane that holds a control character, and widths are measured in terminal cells. [Troubleshooting](troubleshooting.md#the-harnesses-panel-is-not-offered) covers a panel that is missing, cut or showing `Quota unavailable`. The sessions it was tried in are listed in the handoff of 2026-10-17.

### The /spend panel

`/spend` opens a pane with the list-price spend of this session. It exists only in an Aether session, the one started with the agent `aether:lead`. It calls no model and writes nothing to the transcript, including while the figure is still being read, and `Esc` or `x` closes it. From the shell the same figure is `aether-report --spend [--session <id>]`. The panel always passes this session's id. Without `--session`, the command reports the session that wrote last.

The dollars are list price, not a percentage of the quota and not what a subscription charges. The total is the Lead's turns and the agents', split by model, by effort and by role, plus the calls to other harnesses and their dollars.

The same id keeps adding when you resume it: `/resume`, `/compact`, or closing the session and coming back. Another id is not linked to the one before it. `--fork-session` and `/clear` each start a new id, and the earlier one stays its own session.

A model with no price is listed and is not added to the total. The count of resumptions is approximate: a resumption is a gap of more than an hour between two consecutive events of that id, and the pane labels the count `approximate`. After a prune, the gap between the archived stretch and what is still on disk is not counted. When part of the record could not be read, the total is what was read and the figure says `incomplete`. With no record the pane says `No spend recorded yet`. It does not show a total of US$ 0.00, and it does not show another session.

[Troubleshooting](troubleshooting.md#the-harnesses-panel-is-not-offered) covers a `/spend` that is not offered, for the same reason as `/harnesses`. The ceiling of an autonomous run is another figure, and it still leaves out the Lead's own turns ([Autonomy](autonomy.md#autonomy-1)).

## Codex

Codex is OpenAI's coding agent, the `codex` CLI, on a ChatGPT Plus plan. It is a work harness like the others: the `harnesses` option lists it with them, in the registry order `agy, codex, grok, cursor, muse`, and superdelegation sends it calls by the same rule, order and reserve. What follows is what the adapter does.

- **Models and roles.** The lane table has three models, each at the five efforts `low`, `medium`, `high`, `xhigh` and `max`: GPT-6.1 Sol (`gpt-6.1-sol`, roles implementer, supervisor and reviewer), GPT-6.1 Terra (`gpt-6.1-terra`, implementer and supervisor) and GPT-6 Luna (`gpt-6-luna`, implementer). Design seats are not among their roles.
- **Tiers.** AA rescored every model on 2026-10-29 and the table is on one scale; the table was refreshed on 2026-10-30. With the same reset for every quota, the rule gives Terra low to the first step (Haiku high), Sol low to its correction (Haiku xhigh), Terra high to the step of Sonnet high, and Sol xhigh to the step of Opus high. The costs are those AA's model pages gave on 2026-10-30; with the costs of 2026-10-26 the last two were Terra medium and Terra max. Terra low reaches 15.2 % of Terminal-Bench against 21.7 % of Haiku high, which the rule does not see. The rule picks by cost, so another harness can win, and on this table it does not: the same four tiers hold when only Codex is open and when agy, Codex, Grok and Muse are open together, because those Codex pairs cost less than the other pairs that also reach the points.
- **Left out.** GPT-6 Astra waits for GPT-6.1 Astra, as Fable 5.1 waits for Fable 5.5. Also left out: `gpt-6-sol`, the `gpt-5.6-*` models, the hidden `gpt-reserve` and `codex-auto-review`, and the effort `ultra` (Artificial Analysis does not measure it).
- **Quota.** Codex's quota is read with `account/rateLimits/read` of `codex app-server`, without calling a model and without opening credentials. Both windows are read, the 5 hours and the weekly one. A quota refusal is known by the reading, not by words in the answer: the call is quota when a later reading shows a window under the reserve.
- **How a call runs.** In the unit's worktree, Aether runs `codex exec` with `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, the sandbox on, no approvals, and `--output-schema` when the role asks for a structured answer. That keeps out the owner's `config.toml`, rules, session files, `AGENTS.md` and hooks as far as the Lead measured on 2026-10-29 (the measurement is in the handoff of 2026-10-30 and in the run's diary). A global `~/.codex/AGENTS.md` still reaches the model with every flag the adapter passes (the note in front of the prompt asks Codex to ignore its orders); the owner's was generated by oh-my-codex and he removed it on 2026-10-30, after which Codex answered that no global instructions file was loaded. The owner's Orca hooks cannot act because the lane environment drops every `ORCA_*` variable. The way to remove that limit is a private `CODEX_HOME` that holds the owner's session. That touches credentials and waits for the owner.
- **Fallback.** When Codex is missing, has no session, is out of quota or fails during the call, the same call runs on the native agent, and nobody is asked a question. The failure is logged with its cause.
- **Costs.** All fifteen are measured: the cost per index task that Artificial Analysis's model pages gave on 2026-10-30 (Sol max US$1.272, Terra max US$0.961, Luna max US$0.152). On 2026-10-26 only Sol max (US$0.724) and Luna max (US$0.068) were known and the other thirteen were estimates anchored on them, with Terra at half of Sol; AA's re-score changed the basis of the cost, and Terra turned out to cost three quarters of Sol at max, not half.

## Muse

Muse Code is Meta's coding agent, the `muse` CLI. It is the fifth lane harness, last in the `harnesses` list (`agy, codex, grok, cursor, muse`), and superdelegation sends it calls by the same rule, order and reserve as the others (see Parallel and models below). What follows is what the adapter does; the design is in [spec 008](../../specs/008-muse-harness/spec.md) and the Muse decision in [decisions](../decisions.md).

- **How a call runs.** In the unit's worktree, Aether runs `muse exec --json --provider meta --model <model>`, with `--reasoning-effort` set to the effort of the pair that took the call, and `--output-schema` when the role asks for a structured answer. The call takes no standard input and asks nobody for anything: `--disable-approval`, `--disable-request-user-input` and `--disable-reminders` are on, and the run stops after 200 model steps. The reply, the failure reason and the token usage are read from the JSON records, and they come back as those of any other harness.
- **The sandbox stays on.** `--disable-approval` takes away only Muse's approvals. Muse's own sandbox runs the commands, and the workspace is not trusted, so Muse loads no project rules and starts no subagents on its own. The call carries none of `--yolo`, `--disable-sandbox`, `--trust-workspace` or `--api-key-stdin`. If the sandbox does not start, the call fails and the unit runs on the native agent; Aether never repeats it with the sandbox off.
- **Privacy.** Contributor mode is off on every call (`--contributor-mode off`) and no option turns it on, because Meta trains on the content of a run when it is on. A model whose id ends in `-contributor` is never put in the table nor called. `--no-foreign-personal-context` keeps Muse from loading rules, skills and memories that you keep for other tools.
- **Account.** Aether does not sign in for you: it never runs `muse login`, never opens Muse's credential files and does not use `META_API_KEY` (a lane's environment drops variables with `KEY`, `TOKEN` or `SECRET` in their name, and this harness is meant for your subscription, not a per-token key). Sign in to Muse yourself, once, in your own terminal.
- **Quota.** Aether does not read Muse's quota before a call. It knows it from what Muse reported at the end of its last call: the 5 hour window and the weekly one, kept in `lanes/quota/muse-observed.json` in the plugin's data directory. When the reading is older than 30 minutes (`quotaLifeMinutes`), `aether-lane quota --refresh`, the quota step of each wave and `aether-lane pick` renew it with one minimal call (`muse-spark-1.3` at `minimal` effort, answering `ok`). Before the first call the quota is unknown, which counts as usable on the swarm and lane-pick path and puts Muse after the groups that have a reading. On the delegate path a stale or missing reading is renewed instead: one minimal call takes a new one in the background and the decision waits for it up to 20 seconds, and Muse is left out of that decision when the reading did not land. A failure that carries Muse's own quota datum (never the text of the message) leaves the same 60-minute dry mark as the other harnesses (`dryMarkMinutes`), and a healthy observation from a later call lifts it.
- **Fallback.** Every failure sends the call to the native agent, in its reference pair, without asking you: Muse not installed, `authRequired`, quota spent (only when the failure carries Muse's own quota datum), an `environmentError` from the sandbox, a timeout, `stepLimit`, a model your account does not give (`modelError`), output that cannot be read or lacks the object asked for, and any other non-zero exit. An `environmentError` leaves no mark and the quota is not counted as spent, so the next unit sent to Muse tries the sandbox again.
- **Parallel and models.** Muse has no limit on parallel calls: two `muse exec` in different worktrees ran at once on 2026-10-19 and both came back clean. `model/list` of `muse serve` (muse 1.4.14, checked on 2026-10-27) lists four models: `muse-wonder-1.0`, the one Muse runs by default, `muse-wonder-full-1.0`, `muse-spark-1.3` and `muse-spark-1.2`; on 2026-10-19 it listed only Wonder Full. The lane table has three of them, each in by owner decision, and `muse-spark-1.2` stays out by the owner's decision of 2026-10-27. `muse-wonder-full-1.0` is given by Meta only on the Power and Maximum plans; an account without the plan is refused and the call runs native. Its only figure at Artificial Analysis is at `max` (49.7 in intelligence on the scale of 2026-10-29, 55.8 on that of 2026-10-26) under a family name the models index cannot match to the model id, so the table could not score it at an effort it runs; the entry carries the owner's words in `ownerDecision`, and `plugins/aether/config/pairs.json` has the pair `muse/muse-wonder-full-1.0@high` scored as Opus `high` by that decision: 51.7 points and no cost per task. With no cost it goes last in its quota, and it takes the calls that ask up to 52.7 points, down to Opus `high`, and not those of Sonnet `max`, Opus `xhigh` or Opus `max`. `muse-wonder-1.0` enters at `max` only, as the pair `muse/muse-wonder-1.0@max`, the effort of its figures (43.3 points, 0.52 in Terminal-Bench, US$ 6.952 cost per task; above Sonnet `high` and under Sonnet `xhigh`), also by owner decision for the same reason about its name; it has not been called for real through the adapter, and a call that fails is replaced by the next pair. `muse-spark-1.3` has five pairs in `config/pairs.json`. `max` (36.4 points, US$ 2.386 cost per task) is measured. `low`, `medium`, `high` and `xhigh` (17.8, 22.5, 28.7 and 33.9 points, US$ 0.232, 0.534, 0.824 and 1.438) are estimates of 2026-10-30, taken from the curves of Haiku and Sonnet (points) and of Haiku, Sonnet and Opus (cost) because Artificial Analysis measures Spark only at `max`; `minimal` has none. Those pairs do not take a Haiku or Sonnet call ahead of Terra: they cost from US$ 0.232 to US$ 1.438 per task against US$ 0.071 for Terra `low`. Add `muse` to `harnesses` and, with `superdelegation` on, it competes for calls; `scripts/lane-smoke.js muse` calls it with the table's model, or the one you name, and spends quota, so run it on purpose.
- **Seen in real calls (2026-10-19, muse 1.4.11).** A clean call takes 5 to 12 seconds and about 54,000 input tokens for a one-line task, most of it Muse's own instructions. `allowance` arrives in the usage record in snake_case, with a `window` and a `weekly` block (`used_percent`, `resets_at_ms`) and no tier, and the quota the adapter keeps from it reads as the 5 hour window and the weekly one. `--output-schema` takes the roles' schemas, the sandbox runs inside WSL2, the subscription covers `muse exec`, and tool calls appear in the JSON records. Not seen: a failure in the middle of a run. Muse's own `--max-model-steps 1` did not give one: the run never ended and the lane's time limit killed it (the adapter passes 200).
