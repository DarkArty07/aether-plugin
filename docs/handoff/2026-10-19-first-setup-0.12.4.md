The owner asked why their launcher did not work, why the theme did not show and why `/harnesses` was missing, then for a launcher and a skill that arrive with a new installation, and said «publica el panel y publica el lanzador y la skill para que caiga en la nueva instalación y esté en el repo».

## 2. Found in this session

- **Why the theme did not show.** `~/.local/bin/aether-lead` was a copy of `scripts/aether-lead` from 14 October, before the `theme` setting was added on 16 October. A copy goes stale; the owner's copy is now a link to the script, with the old one kept as `aether-lead.bak-20261019`.
- **Why `/harnesses` was missing.** It was built and tried in real sessions, but its files were never committed: the branch `feat/harness-panel` sat on the same commit as `main`, with no remote branch, pull request or tag. It shipped as 0.12.3 in this session. The changelog, the lanes guide and the 0.12.3 handoff cited an evidence page, `specs/006-delegate-router/evidence/panel/README.md`, that was never written (it is in no commit of any branch); they now cite the handoff, and the captures of those sessions are not kept.
- **What Claude Code lets a plugin do** (documentation read by a delegate on Haiku, not measured here). There is no install event or post-install step; the plugin's `bin/` is on the Bash tool's `PATH` only, never the person's shell; a plugin's own `settings.json` honors only `agent` and `subagentStatusLine`, and `agent` there would start the Lead in every session where the plugin is enabled; `theme`, `effortLevel` and the permission mode cannot be set by a plugin, and there is no `--theme` flag; no plugin skill can switch the main agent of a running session. That is why the setup is a skill the person calls once.
- **The owner's other `aether`.** `~/.local/bin/aether` is another project's command, so `aether` is not usable; `aeth` is the default. `~/.local/bin/claude-aether` is a 415-line Python wrapper of that project that starts Claude Code through its local router (`127.0.0.1:8787`); the router service is active, the wrapper was last used from fish on 3 October, and nothing in this repository calls it. It was not touched.
- **Quirks of the tools.** In a worktree-isolated session the shell guard refuses a command that mixes `git` with other constructs, and one that assigns `HOME` inline; test drivers go in a script file. `aether-autonomy revoke` verifies that its quote is in the owner's messages of that session, so the Lead cannot withdraw a grant with words of its own: the session grants for `merge-main` and `publish` made for these releases are open until the session ends.
- **An independent review** (Opus at `high`, given the code and the design and none of the Lead's conclusions) found one defect of the first weight and several smaller ones, and the Lead had checked the happy paths itself in a throwaway home first. Fixed before the release, each with a test that failed first: a version directory that is not shaped like `0.12.3` (a commit hash from another marketplace) could win; a launcher without the exec bit could win over a runnable older one; one looping or unreadable cache entry made the run exit 1 after the stub was written, or hid every release from the JSON; a name of any length was accepted, and so was `claude`, whose stub would run itself; and the skill did not say what to do on exit 1 or when the command is not found. Known and left as they are: a process that creates a file of the stub's name in the same few microseconds between the last check and the rename would be overwritten (commented above `replaceOwn`); `0.13.0-beta.1` sorts above `0.13.0`; the stub reads no `installed_plugins.json`, so a release that was uninstalled but is still in the cache can be chosen; `--check` says 0 where the real run would fail on a `--dir` that is a broken link; with `HOME` unset the stub looks in `/.claude`; `scripts/aether-lead` needs `readlink -f`, which macOS has from 12.3.
- **Not measured:** the skill's footprint in a plain session, which comes from the documentation of `disable-model-invocation` (the validator does not check that field); that the plugin cache keeps this layout on a Claude Code release other than 2.1.303; `CLAUDE_CODE_PLUGIN_CACHE_DIR`, which the stub does not read; and the whole flow in a fresh install of a published release.

## 3. What is left, and what waits for the owner

- **Run `/aether:first-setup` once** in a new session with 0.12.4 installed, and then `aeth`: the theme should show and, with 0.12.3 or later, `/harnesses` opens. Nobody has run it on the real home.
- **The name.** `aeth` is a default chosen by the Lead; `--name` changes it. The owner has not chosen between `aeth`, `claude-aether` or another.
- **The old wrapper.** Moving `~/.local/bin/claude-aether` aside (`mv … claude-aether.bak`) waits for the owner's word, and only makes sense if they no longer start Claude Code through that router.
- **The entry screen** the owner wanted attractive, which was left for later. The proposal is three prototypes as terminal scripts (A: a splash that starts at once; B: the same with a short menu; C: no screen) with no library: Node 22's `readline`, true-color ANSI and half-block characters, and the sprite in `assets/brand/sprites/claude-aether.txt`. It lasts until Claude Code takes the screen.
- **Adding `grok` to `harnesses`, and the router's mode.** The owner's `router` option is `command` in `~/.claude/settings.json` since this session, for sessions started after it; the other decisions of the 0.12.2 and 0.12.3 handoffs are as they were.

## 4. How to check it

- **A release of this change:** `gh pr list --search "first-setup"`, `git tag --list 'aether--v0.12.4'`. To move the installed plugin: `claude plugin marketplace update aether-plugin`, then `claude plugin update aether@aether-plugin`, then a new session.
- **The command without a model:** `node plugins/aether/bin/aether-first-setup --check --dir <a temporary directory>`; `npm test` runs its 32 tests.
