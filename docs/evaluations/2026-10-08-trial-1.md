# Trial 1: Aether mode against normal mode (2026-10-08)

**Question.** Does Aether mode cost less and take less wall-clock time than normal mode, at equal quality? This is the gate to the published project (spec A9 and §13).

**Verdict: the gate passes, with the caveats below.** Aether mode finished the same plan:
- 3.9 times faster: 6 min 11 s against 24 min 25 s;
- 2.8 times cheaper: $1.98 against $5.60.

Both runs passed the hidden acceptance suite (33/33) and their own tests, and both ended with no open critical or important finding. Normal mode's deeper review left its build slightly more hardened beyond the spec.

## Setup

**Fixture.** `tasks` is a task-list library and CLI for Node.js 22, with no dependencies.
- [Spec](trial-1/fixture/spec.md).
- [Plan](trial-1/fixture/plan.md): a contract plan per A10, with 7 tasks across 2 areas (`core` and `cli`) in 3 waves: tasks 1–5, then 6, then 7. Six tasks are on the Haiku tier and one on Sonnet. The plan's tests total 24.

**Hidden acceptance suite.** [33 cases](trial-1/fixture/acceptance-suite.js), each following from the spec, none repeating a plan test.
- The Designer wrote it before the runs, and neither session saw it.
- It was validated against a throwaway reference implementation, which passed all 33 cases and all 24 plan tests. The reference was then deleted.

**Sessions.** One fresh headless session per mode (`claude -p`), run one after the other.
- Opus 5.5 main session at the owner's default effort (`xhigh`);
- superpowers 6.4.1 on;
- claude.ai MCP connectors off;
- permissions bypassed;
- a $40 cap and a 3-hour timeout (neither was reached).

**Starting point.** Each mode got its own copy of the fixture, with the integration worktree `.worktrees/trial` already on branch `feature/trial`. The harness and prompts are in [trial-1/harness](trial-1/harness).

**Aether mode:** the plugin and `enableWorkflows`. The Designer followed the `swarm` skill: compile, `/aether:run`, report, act on the result, `finalize`.

**Normal mode:** superpowers `subagent-driven-development`, with its per-task reviews, its final review and its fixes.

**Fairness note.** The normal-mode session read the plan's Aether tiers and used them for its own model choice:
- Haiku implementers, and Sonnet for task 6;
- Sonnet task reviewers;
- an Opus final review.

So both modes ran the same models per task, and the comparison measures orchestration, not model choice.

## Where the difference comes from

- **Orchestration in code, not in the Opus context.** Normal mode's Opus controller ran 48 turns: it read briefs, dispatched each task, read each report and review, and updated its ledger. That came to 4.9 million cache-read tokens and 90,000 output tokens on Opus. Aether's Designer took 15 turns, because the workflow script carries the loop. All of Aether's Opus use, the Designer and the final reviewer together, came to 1.4 million cache-read tokens. Opus is 83% of Aether's cost and 76% of normal mode's.
- **Parallel waves.** Aether built the five tasks of the first wave at the same time. Normal mode is serial by design: superpowers' subagent-driven development forbids parallel implementers.
- **Review cost.** Aether's 7 Sonnet supervisors read compact review packages, at about $0.03 per call. Normal mode's 10 Sonnet dispatches (7 task reviews, task 6's implementer, the fix wave and its re-review) averaged about $0.13.

## Quality beyond the spec

On everything the spec states, the two builds are equal: 33/33. On behavior the spec does not cover, the builds differ:

| Behavior | Aether build | Normal build |
|---|---|---|
| `list --tag @home` | prints "No tasks." (its final review rated this minor and deferred it) | finds the task (its final review rated it important and fixed it) |
| `list @home`, a stray word | ignored, exit 0 | refused, exit 2, with a hint |
| Saving through a symlinked `tasks.json` | replaces the link with a file | follows the link and keeps the file's mode |
| A corrupt store | one-line message, exit 3 | one-line message, exit 1 |

Normal mode bought this hardening with its heavier review: a Sonnet reviewer per task that explores the codebase, and a re-review after the fix wave. In this trial, Aether's review depth was lower, in line with its lower cost.

## Threats to validity

- **Sample size:** one fixture and one run per mode. Model sampling varies from run to run, and a different plan could favor either mode.
- **Fixture size:** the fixture is small, and its contract plan pins most behavior with tests, which suits cheap implementers.
- **Run conditions:** both runs were headless, with bypassed permissions and MCP connectors off. Interactive use with permission prompts or connectors would add time and cost to both.
- **The fix step:** Aether's Designer fixed the final-review finding itself, while normal mode used a fix wave of subagents. Each followed its own method.
- **Cost figures:** they are Claude Code's list-price figures. The plugin's OpenRouter pricing of the same tokens came to $2.06 and $5.72, because it assumes the cache-write lifetimes. Correction from trial 2: Claude Code charges Sonnet 5.5 cache reads at $0.20 per million tokens, where OpenRouter charges $0.10. All its other rates equal OpenRouter's. Here that raises Claude Code's Sonnet figures by $0.02 and $0.11.

## Follow-ups

- **A second trial:** a larger plan, with frontend work and a run that needs a relaunch, to test escalation and blocked units.
- **Review depth:** measure whether giving Aether's supervisor or final reviewer the codebase-exploring checks of superpowers' task reviewer closes the hardening gap, and at what cost.
- **Real usage conditions:** repeat with the owner's normal permission mode and connectors.
