# Ops without a model: the spike and the mini run

- **Date:** 2026-10-10
- **Claude Code:** `claude --version` gives `2.1.296 (Claude Code)`; Node.js 22.22.0, Linux
- **Tree under test:** branch `feature/ops-in-mod`, plugin `aether` 0.7.0 with decision A30
- **Brief:** [the handoff](../handoff/2026-10-10-ops-without-llm.md), §7 steps 1 to 3
- **Result:** the spike passed, so the change was built (§7 step 2) and the fallback reductions of §7 step 5 were not needed.

## Isolation

Every `claude` call ran through a wrapper that empties the environment and points Claude Code at scratch directories and at the fake model:

```sh
exec env -i PATH="/opt/node22/bin:/usr/local/bin:/usr/bin:/bin" TERM=dumb IS_SANDBOX=1 \
  HOME="<S>/home" CLAUDE_CONFIG_DIR="<S>/cfg" \
  ANTHROPIC_API_KEY=sk-ant-fake-spike ANTHROPIC_BASE_URL="http://127.0.0.1:$(cat <S>/fake/port)" \
  CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 DISABLE_AUTOUPDATER=1 /opt/claude-code/bin/claude "$@"
```

- `<S>` is a scratch directory outside the repository. No real `~/.claude` was read or written, and no model request left `127.0.0.1`.
- The fake model is `tests/fixtures/fake-model.js`, unchanged. It bound port 0 each time, and the system chose the port: 34593, 40991 and 36523, among others, for the spike, and 43501, 41777 and 44593 for the mini runs.
- `npm run check`'s `claude plugin test` and `claude plugin validate` ran through the same kind of wrapper, with their own scratch `HOME` and `CLAUDE_CONFIG_DIR`.

## Spike

A throwaway plugin `spike` with three parts:

- an agent `spike:ops`: a copy of `aether:ops`, Haiku, `tools: Bash`;
- a two-hook mod:
  - `agent.spawn` reads a `SPIKE-RUN <argv>` line from the prompt and keeps it under the `agentId` that `next(e)` returns;
  - `turn.step`, on that agent's first step, runs the argv with `$.process.run`, yields `tool` (`StructuredOutput`), `input` and `stop` chunks, and returns a `TurnStepResult` with `usage: null`. On any rejection it calls `next(e)`;
- small bins: `slow <seconds> <exit>`, `big <bytes>`, `envdump <label>` and `spawner detached|attached`.

Each session was `<S>/c -p SPIKE-MAIN-<n> --plugin-dir <S>/plugin --dangerously-skip-permissions`. The fake model answered the main session with one `Workflow` call. Every case was an `agent()` call with `agentType: 'spike:ops'` and the schema `{ exitCode: integer, stdout: string }`. An ops agent that reached the model got Bash, then `StructuredOutput`, from the script.

| Case | What the mod did | Model requests of that agent | What `agent()` returned |

The mod's log of each `$.process.run` result had `exitCode`, `stdout` and `stderr`, and also `isStdoutTruncated` and `isStderrTruncated` (`false` for the 1 MB output). The 20 MB case's log was too large for `$.fs.write` (4 MiB), so its flags were not recorded; its `stdout` came back at exactly 4,194,304 characters.

The workflow ran two agents at a time on that machine, so long calls overlapped: `slow 150` with `slow 330`, and `slow 560` with the other cases of its session.

What the transcripts show for an answered agent (`agent-<id>.jsonl` under the workflow's directory): the agent's first user message, then one assistant message on `claude-haiku-5-5` with every usage count 0 and one `tool_use` named `StructuredOutput`, then its `tool_result` "Structured output provided successfully". The agent made no further step.

The `agent.spawn` event's `e` had `tool_use_id`, `prompt`, `description`, `subagentType`, `provider`, `model`, `parentModel`, `permissionMode`, `background`, `fork` and `workflow` (`{ runId, agentIndex }`). Its `prompt` was the workflow's text, without the harness frame. The answered agent's first `turn.step` had `index: 0` and the agent's id.

### The environment

`envdump` printed the environment and made a `git commit` in a repository whose `pre-commit` hook writes a file.

- **Under `$.process.run`, compared with the Bash tool of the same session,** the child lacked `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_EXECPATH`, `CLAUDE_PID`, `CLAUDE_EFFORT`, `GIT_EDITOR=true`, and the `bin/` directory of each plugin on `PATH`.
- Because the session started under `env -i`, `SHELL`, `PWD`, `SHLVL` and the Nix variables were missing from it too. They come from the shell profile that the Bash tool sources.
- **The `pre-commit` hook ran under both.** "Git runs with repo hooks off" did not reach git started by the command.
- No git call of `aether-wt` or `aether-lane` opens an editor: each merge passes `--no-edit -m`, and each commit `-m`. Their runtime commands read no variable that Claude Code adds to Bash.
- What they start does run in this environment: the plan's test command, inside `aether-wt merge`, and agy. The second mini run below measures what that changes.

## Mod tests and checks

- `tests/ops-command.test.js`, 12 tests, written before the parser, `hooks/ops-command.mjs`. One test runs the real `run.workflow.js` in the workflow harness, with and without lanes, and with a lane whose digest never matches. Every ops prompt it builds parses to the command the harness reads from it. The nine forms appear: `aether-wt merge`, `remove`, `diff --final` and `sweep --run`, and `aether-lane status`, `start`, `wait`, `result` and `stop`.
- `plugins/aether/hooks/ops.test.ts`, 17 tests under `claude plugin test`. Against `main`'s `register.js` the 14 tests of the new behaviour fail and the 3 of what must not change pass. With the change all 34 mod tests pass, the 17 of the usage meter included.
- `claude plugin validate plugins/aether --strict` passes. It now lists `$.process.run` among the module's calls.
- `npm run check`, through the wrapper: 387 node tests with none failing (one skipped, as on `main`: `aether-voice` cannot fail to read a file as root), the 34 mod tests, and both manifests.

## Mini run

Two throwaway repositories with the same history, `repo-mod` and `repo-deny`. Each had:

- a one-task plan (`tests/plan-fixtures.js`, test command `node -e "process.exit(0)"`);
- the run compiled by the plugin's own `aether-plan compile --run <id> --no-lanes`;
- the unit worktree from `aether-wt ensure`, with one commit of `src/t1/a.js`.

The plugin was a copy of this branch's `plugins/aether` without its `dependencies` field: without network, `superpowers` cannot be installed, and the plugin does not load without it (F12). Each session started as `--agent aether:lead`, so it was an Aether session, and ran one workflow. That workflow sent six `aether:ops` calls, with prompts built exactly as `opsPrompt` builds them and the schema `OPS_SCHEMA`.

- **`repo-mod`:** `--plugin-dir <copy>`.
- **`repo-deny`:** `--plugin-dir <copy> --plugin-dir <denyproc>`. `denyproc` is a one-hook plugin whose `process.run` hook returns `{ deny }`, as an administrator's could. For that session the fake model ran each command with Bash.

| Command | Through the mod | Through the model (Bash) | Same output |
|---|---|---|---|
| `aether-lane status <run>` | exit 0, `{"harnesses":{"agy":{"installed":false,…}}}` | the same | yes |
| `aether-wt merge <run> task-1` | exit 0, `{"merged":true,"commit":"…"}` | the same | yes |
| `aether-wt remove <run> task-1` | exit 0, `{"removed":true,"patch":null}` | the same | yes |
| `aether-wt diff <run> --final` | exit 0, `{"path":"…/packages/final.diff","base":…,"head":…}` | the same | yes |
| `aether-lane wait <run> task-1-1-implement` | exit 1, `{"error":"no such lane call: task-1-1-implement"}` | `Exit code 1` and the same line | yes, but the Bash tool's text adds `Exit code 1` |
| `aether-wt sweep --run <run>` | exit 0, nothing left | the same | yes |

- **Model requests:** the mod session made 3, all of the main session. The deny session made 15: 3 of its main session and 12 of the ops agents, Bash then `StructuredOutput` for each.
- **The usage meter:** in the mod session it listed the 6 ops agents with no entry, and in the deny session it recorded their 12 requests.
- **The repositories at the end:** the same tree (`bb4587c`), one worktree each, the branches `feature/x` and `main`, a clean status, and the same `final.diff` once hashes and run ids were masked.
- **The six calls took about 2 s in all through the mod,** from the start of the session to its end.
- **A first attempt** ran with no git identity in the scratch `HOME`. Its merge failed with "Committer identity unknown", and the mod returned that failure as `aether-wt` printed it. The repositories were rebuilt with `user.name` and `user.email` set.

### The mini run again, after the review

The review (below) changed the mod: the bins now start as `node <bin>`, and other details. The run was repeated with a new copy of the branch, in two more pairs of repositories, through the mod and through the deny plugin, and once more with the code of the final check. Both times gave these results:
- **The same plan as above:** the six outputs and the final state were again the same both ways, with 0 model requests for the ops agents through the mod and 12 through the model.
- **A plan whose test command needs a variable from `CLAUDE_ENV_FILE`:** `node -e "process.exit(process.env.AETHER_LANES ? 0 : 3)"`. Aether's own session-start hook exports `AETHER_LANES` that way.
  - **Through the Bash tool,** the merge passed: `{"merged":true,…}`.
  - **Through the mod,** it failed: `{"merged":false,"reason":"tests","exitCode":3,"reverted":true,…}`. The merge was undone and the integration branch kept its tree. `aether-wt remove` then saved the unit's work as a patch.
  - The other four commands gave the same output both ways.

## The review

Four reviewers read the change: for correctness, security, parity with the model path, and the docs. For each reviewer, a second agent then tried to refute its findings. After the fixes, two more agents checked the code delta and the docs, the pull request text included. These changes came from it:
- **The bins start as `node <bin>`.** When `node` is not on the Claude Code process's `PATH`, the call is refused at once and the model path runs it. Before, the bin's shebang made `/usr/bin/env` exit 127, and the mod answered that.
- **A bin that fails to load goes to the model.** Such a bin changed nothing: node printed `SyntaxError` (a node too old for it) or `Cannot find module`, and nothing reached standard output. A bin that ended without its line for any other reason, killed for instance, is reported as an error with the last line of its standard error, and never handed to the model. A final check found that the first version of this rule handed a killed `merge` to the model too.
- **A merge stopped at the timeout says so.** Its merge commit may be on the integration branch, untested.
- **An answered agent never reaches the model.** If an agent takes another step after the mod's answer, the mod ends it with a text answer, so a renamed or refused `StructuredOutput` cannot make that agent's model run the command again. The workflow's own retries of `remove` and `sweep` would still run them again.
- **The timeout tests check each of the two signs alone.**
- **The parser became `ops-command.mjs`,** so `node --test` loads it without a module-type warning.
- **The docs now say:**
  - the permission rules, the environment, agy's detection on the process's `PATH`, and the 10-minute limit for a merge's tests;
  - that any workflow in an Aether session, not only `aether:run`, gets the mod's answer, for any repository and run its prompt names;
  - and what a policy that refuses the whole mod turns off.

Not changed, because the refuting agents found no realistic path:
- gating on the permission mode;
- tying the `cwd` to the session's repository;
- checking the `lanes` option before an `aether-lane start`;
- recording zero-token usage entries for the answered steps.

## What was not verified

- **A real swarm run** (`aether:run`), by the owner's constraint. The workflow's own code is unchanged, and the harness test above covers its prompts.
- **A lane call through the mod with a live runner and agy.** `aether-lane start` was not run for real. The spike showed that a detached grandchild survives and does not hold the call.
- **What a person sees in the interactive `/plugin` screens,** and a real managed policy. The deny was a user-tier plugin.
- **A person's interrupt during a long `$.process.run`.** `ProcessRunInit` has no signal, so the command may run on to its end or its timeout.
- **Sessions started from an IDE or the desktop app,** whose process `PATH` may differ from the shell's, and macOS and Windows.
- **A merge whose tests outlast 10 minutes.** From the code and F28, it is stopped after its merge commit and before its revert. It was not run.
- **What the session's permission rules would have done.** Every session here ran with `--dangerously-skip-permissions`. The mod's path does not consult them, by design.
- **More than two long `$.process.run` calls at once.** Lanes allow four calls in flight, each with its own `aether-lane wait`.
- **The guard for an answered agent in a live session.** Only the mod tests reach it, because on 2.1.296 an answered agent takes no further step.
