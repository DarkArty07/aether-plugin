# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

The development repository of **Aether**, a Claude Code plugin that adds an opt-in "Aether mode": a Lead agent turns the owner's intent into a reviewed spec and plan, builds it itself, through delegate tasks or with a parallel swarm, and reports in one brief. The plugin is `plugins/aether/`; the root holds the marketplace (`.claude-plugin/marketplace.json`), the tests, `scripts/`, `docs/` and `specs/`. Node.js 22, CommonJS, **no dependencies**: the root `package.json` is private and only has scripts.

## Commands

```
npm test                                   # node --test "tests/*.test.js": bins, libs, workflow scenarios, docs facts
node --test tests/guard.test.js            # one file
node --test --test-name-pattern="R10" tests/docs-facts.test.js   # one test, by name
npm run test:mod                           # claude plugin test plugins/aether (the mod: hooks/*.test.ts)
npm run validate                           # claude plugin validate on the plugin and on the marketplace, --strict
npm run check                              # all three; run before a PR or a release
```

- **Try a branch:** `scripts/aether-lead --plugin-dir <worktree>/plugins/aether` (same as `claude --plugin-dir … --agent aether:lead --effort xhigh`). It loads the tree instead of the installed release and uses the data directory `~/.claude/plugins/data/aether-inline/`.
- **Run a branch's bin by path:** `node plugins/aether/bin/aether-plan check <plan.md>`. In a development tree the `aether-*` names on `PATH` are the *installed release's* bins (issue [#13](https://github.com/DarkArty07/aether-plugin/issues/13)).
- `node scripts/refresh-lanes.js [--write]` refreshes the lane table (needs `ARTIFICIAL_ANALYSIS_API_KEY`); `node scripts/build-models-index.js` rebuilds the models index; `node scripts/lane-smoke.js <harness>` makes one real, quota-spending call: run it on purpose.
- **Release** (full steps in `docs/contributing.md`): the version lives in four places, `plugin.json`, the pin in `tests/launcher.test.js`, the README's `Version X.Y.Z` line and the changelog's first `Version X.Y.Z:` line; tag with `claude plugin tag plugins/aether` (`aether--v<version>`) on `main`.

## Architecture

Read across files; none of this is in one place.

- **Entry and dormancy.** `hooks/hooks.json` runs `bin/aether-session-start` (`lib/session-start.js`) on SessionStart and `bin/aether-guard` before Write, Edit, MultiEdit, NotebookEdit and Bash. Both act only in a session whose agent is `aether:lead` (or one marked in the data dir) and do nothing in a plain session; that dormant footprint is a design invariant, measured in `docs/reference/components.md`. The Lead's rules are the `skills/using-aether` skill, injected as the bootstrap.
- **Bins are thin, `lib/` holds the logic.** Each `bin/aether-*` parses arguments and calls `lib/*.js` by path. `aether-plan` calls `lib/plan-compile.js` to check and compile a Spec Kit `tasks.md` into briefs and waves; `aether-wt` manages unit worktrees and one-at-a-time merges; `aether-lane` calls `lib/lane-command.js` to make calls on other harnesses and run design seats (adapters in `lib/harness/`: agy, codex, grok, cursor, muse; process handling in `lib/lane-process.js`); `aether-exam` keeps and runs the hidden acceptance exam; `aether-autonomy` calls `lib/autonomy-command.js` for the owner's grants and a run's ceilings; `aether-delegate` holds the ladder of the Lead's delegate tasks (below); `aether-report` prices a run from `config/prices.json`, and `aether-report --spend` reads `usage/`, `lanes/` and the delegate log (`lib/spend.js`, token counts in `lib/spend-tokens.js`), not an older decisions journal. Shared helpers live in `lib/common.js`. The router family is `router-marks.js`, `router-pick.js`, `router-quota.js`, `router-renewal.js` and `router-slow.js` (quota readings and marks under `<data dir>/router/`). The families and the loose modules are the table in `docs/reference/components.md`.
- **Workflows.** `workflows/design.workflow.js` (`/aether:design`) and `workflows/run.workflow.js` (`/aether:run`) are scripts for Claude Code's Workflow tool. They call the agents in `agents/*.md` (lead, writer, judge, examiner, implementer, supervisor, reviewer, ops) and take their models and efforts from the plan's Tier, and, with `superdelegation` on, from the one choice function of `lib/superdelegation.js` (the swarm asks it through `aether-lane pick`, the design seats through `lib/seats.js`). Shell steps go to the `aether:ops` agent, which the mod answers itself without a model.
- **Delegates.** The Lead's delegate tasks climb a ladder of models that the system holds, not the Lead ([Delegates](docs/guide/delegates.md), spec 013). Every delegate starts on Haiku; a correction goes to the same model with its own work and concrete findings; a task rises only when the corrections of its step are spent, the same findings come back, or the Lead declares it infeasible with a reason. `lib/ladder.js` is that policy, a pure function over `config/ladder.json`: the corrections of each step and the repeated findings are data, written nowhere in code. `bin/aether-delegate` is its bin (`begin`, `verdict`, `start`, `run`, `wait`, `answer`, `renew`) and the `lib/delegate-*.js` files do the work (`delegate-task` begin and verdict, `delegate-run` and `delegate-chain` an attempt on another harness, `delegate-checks` the checks that run without a model, `delegate-log` and `delegate-report` the log and its report). Only a verdict that goes through `aether-delegate verdict` counts, and an `approve` with a failed check is refused. Every launch, result, outcome, verdict, relaunch and answer is a line of `<data dir>/delegates/log.jsonl`, append-only and one write per line, which `aether-report --delegates` and `/spend` read; the files of each launch are under `<data dir>/delegates/`.
- **Self-observation.** `bin/aether-observe` (`hook`, `read`, `baseline`, `status`, `forget --yes`) is the handler of five hooks (`PostToolUse` of `ScheduleWakeup`, `PostToolUseFailure`, `StopFailure`, `PreCompact`, `SessionEnd`) that act only in a Lead session, and the lib files `lib/observe*.js` do the work: `observe.js` the store under `<data dir>/observe/`, `observe-detect.js` and `observe-calibrate.js` the detectors, `observe-digest.js` the durable summary and the 30-day prune, `observe-read.js` the reading that `SessionEnd` runs by itself, and `observe-dev.js` the only file that reads a conversation, in the development installation (turned on by `aether-lead --dev`, `AETHER_OBSERVE=dev` or the `observedev` option). The standard installation keeps identifiers, classes and counts, never conversation content (spec 014 R10); nothing leaves the machine and an issue is opened only with the owner's yes. Thresholds are in `config/observe.json`. See [Self-observation](docs/guide/observe.md).
- **The mod.** `hooks/register.js` (with `ops-command.mjs`) records every model request of an Aether session for `aether-report` and runs the workflow's own `aether-wt` and `aether-lane` commands without a model call. `hooks/delegate.mjs` (with `delegate-wait.mjs`) hands the Lead's `Agent` calls to `aether-delegate` through `$.process.run`; it never imports `lib/`. It is TypeScript-tested through `claude plugin test`, not through `npm test`.
- **Config.** `plugin.json` `userConfig` is the options table, and `docs/guide/options.md` must match it: `superdelegation`, `harnesses`, `ops`, `deadlines`, `quotabrake`, `brakepush` and `observedev`. `lib/superdelegation.js` `resolveOption` turns superdelegation on only when that option is `true`. `config/ladder.json` (the steps of the delegate ladder and their corrections), `config/lanes.json`, `config/pairs.json` (the pairs of model and effort with their Artificial Analysis figures), `config/models/models.json`, `config/prices.json` and `config/autonomy.json` are data the libs read.
- **The website.** `site/` is the static landing page: vanilla HTML, CSS and JS with no build, in Spanish and English, opened from `file://` or served with `python3 -m http.server -d site`. `.github/workflows/pages.yml` deploys it to GitHub Pages on a push to `main` that touches it, and `tests/site.test.js` holds its references. The README's images are in `assets/readme/`.
- **Method and state.** Spec Kit's layout: each feature is `specs/NNN-<topic>/{intent,spec,plan,tasks}.md`, with `.specify/feature.json` pointing at the current one and the preset in `plugins/aether/speckit/` (also shipped as the `aether:specify`, `plan`, `tasks` and `constitution` skills). Runs write local state to `.aether/` (git-ignored) and, for the installed plugin, to `~/.claude/plugins/data/aether-aether-plugin/` (`runs.jsonl`, exams, lane logs, `delegates/`).

## Working rules

- **Docs are held to the tree by tests.** `tests/docs-facts.test.js` fails a README of more than 160 lines or with its parts out of order, a second `Version` line, a `Version` that differs from `plugin.json`, a relative link or anchor that does not resolve, an `` `aether-<name>` `` code span that is not a file of `plugins/aether/bin/`, a page without `title`, `description` and an integer `order` in its front matter, and a page that `docs/index.md` does not link. Read its header comment before editing prose; exceptions are listed there with a reason.
- **`aether-guard` shapes what an Aether session may write.** Specs, plans, tasks and the constitution are writable only by the Lead and the Writer, the autonomy registry and run states by no agent, and the Examiner writes only under `.aether-exam/`. An irreversible command (`push`, `merge-main`, `publish`, `deploy`, `delete`, `credentials`, `paid-call`) with no grant is recorded in `.aether/pending.jsonl`, and refused when `AETHER_IRREVERSIBLE=enforce`, which `scripts/aether-lead` sets by default.
- **Tests run on throwaway git repos** built by `tests/helpers.js` (`tempDir`, `makeRepo`), which also points `AETHER_LANES_CONFIG` at a missing file so no lane exists unless a test names a table. Workflows are exercised in a harness with stubbed agents and the fake model, so they spend no tokens.
- **Records.** Decisions are numbered in `docs/decisions.md` (A1 onward); bugs, observations and requests for improvement are **GitHub issues**, the only list (`gh issue list`): when you find one, file an issue with the evidence and work from it later, never as a file in the tree. Older docs say «issue 008» with three digits: those were files of a former `docs/issues/` and are now GitHub issues whose body begins «Formerly `docs/issues/NNN-…`»; session handoffs are `docs/handoff/`, and the newest one holds the current state.
- **Do not commit:** `.worktrees/` and `.claude/worktrees/` (worktrees), `.aether/`, and `plugins/aether/tsconfig.json` and `plugins/aether/.claude-plugin/types/`, which Claude Code generates when it loads the mod.
